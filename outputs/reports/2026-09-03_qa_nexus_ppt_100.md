## 一、ROS2 配置、通信与排障（001–030，共 30 题）

### 001｜★ 为什么选 Ubuntu 22.04 和 ROS2 Humble？

**答：**这组版本对应项目的开发基线，Ubuntu 22.04 也是 Humble 的主要支持平台。固定组合便于统一软件包、构建工具和排障方法。选择 ROS2 还服务于项目的自研接口和模块通信需求，但使用 ROS2 本身不会自动提高定位精度。[Humble 官方平台说明][ros-humble]

### 002｜从一台干净的 Ubuntu 开始，ROS2 配置需要哪些步骤？

**答：**先检查系统版本、架构和 UTF-8 locale，再按 Humble 官方安装流程配置软件源和安装所需包；之后加载环境，运行通信例程，最后构建项目工作空间。安装软件、环境生效、节点通信和项目运行是四个不同的检查环节，不能只看安装命令是否结束。

**追问要点：**软件源配置命令应按当时的官方安装入口核对，不复用来源不明的旧密钥脚本。[官方安装入口][ros-install]

### 003｜`ros-humble-desktop` 和 `ros-humble-ros-base` 怎么选？

**答：**Desktop 面向带图形工具的开发环境，适合需要 RViz 和演示工具的电脑；ROS Base 提供基础通信和运行能力，适合按需部署。对树莓派应根据实际节点依赖安装，不能因为选了更小的安装集合，就断言视觉算法能实时运行。

### 004｜★ 为什么安装了 ROS2，新终端却提示找不到 `ros2`？

**答：**常见原因是新终端没有加载 ROS2 环境。`source` 会把当前终端使用的命令和包路径设置好；它不会重新安装 ROS2。先检查当前发行版，再检查项目 overlay，避免加载到了另一个 ROS 版本。[ROS 环境配置][ros-env]

```bash
source /opt/ros/humble/setup.bash
printenv ROS_DISTRO
printenv ROS_VERSION
which ros2
```

### 005｜NEXUS 在 WSL 环境里做了什么有针对性的配置？

**答：**项目的 `activate_humble.sh` 在加载 Humble 前设置 `TMPDIR=/tmp`。仓库说明指出，WSL 可能继承指向 Windows 挂载目录的临时路径，从而影响 pytest 在 ament 配置阶段的检查。这是处理已记录的环境问题，不能概括成“WSL 下所有测试问题都来自临时目录”。

```bash
cd /root/nexus_workspace/NEXUS/code/ros2_ws
source scripts/activate_humble.sh
```

### 006｜underlay 和 overlay 是什么？为什么加载顺序重要？

**答：**系统安装的 ROS2 通常是 underlay，项目工作空间是叠加在上面的 overlay。后加载的包路径可以覆盖前面的同名包，因此顺序决定实际运行哪个版本。构建与运行最好使用清楚区分的终端环境，避免旧工作空间影响新构建。[官方工作空间教程][ros-workspace]

### 007｜`ament`、`colcon` 和 ROS1 的 `catkin` 有什么区别？

**答：**ament 提供 ROS2 包的构建与测试约定，colcon 负责按依赖关系组织多个包的构建；catkin 是 ROS1 常用的构建体系。项目的 ROS2 工作空间使用 `colcon build`，不能把 ROS1 的构建命令直接套过来。选择构建工具还要看包自身的构建类型。

### 008｜★ 项目怎样完成一次可检查的构建与测试？

**答：**先按工作空间说明加载环境并补齐声明的依赖，再构建、运行测试和读取测试汇总。构建完成只能说明编译或安装步骤通过，不能替代行为测试；测试命令结束后还要看是否有失败，或测试根本没有被登记。

```bash
cd /root/nexus_workspace/NEXUS/code/ros2_ws
source scripts/activate_humble.sh
colcon build --symlink-install
colcon test
colcon test-result --verbose
```

**追问要点：**`--symlink-install` 方便部分源码修改直接生效；修改编译代码、安装规则等内容仍需重新构建。[colcon 工作空间说明][ros-workspace]

### 009｜为什么包目录存在，`ros2 run` 仍然找不到它？

**答：**源码存在不等于包已被构建、安装和发现。应检查包是否被 colcon 识别、`package.xml` 是否正确、可执行入口是否被安装，以及当前终端是否加载了对应 `install/setup.bash`。Python 包还要检查入口注册；C++ 包要检查目标的安装规则。

### 010｜talker-listener 测试具体怎样做？

**答：**在两个已加载同一 ROS2 环境的终端中，分别运行发布和订阅例程。观察 listener 是否持续收到 talker 发出的消息，再用节点、话题查询确认通信关系。只有例程包已安装时，下面命令才可直接运行。

```bash
# 终端 A
ros2 run demo_nodes_cpp talker
# 终端 B
ros2 run demo_nodes_py listener
```

### 011｜★ talker-listener 成功，证明整个项目已经跑通了吗？

**答：**它证明这次测试环境下的基本发现、发布和订阅可以工作。如果测试在同一台机器上，也没有证明跨机器通信正常。图像带宽、时间同步、坐标变换、算法延迟和定位精度都需要另外检查。因此 PPT 第 6 页展示的是通信基础验证。

### 012｜节点、话题、服务和动作分别适合什么？

**答：**节点承载具体功能；话题适合持续数据流，例如图像和位姿；服务适合短时请求与响应，例如读取或更新配置；动作适合需要进度反馈和取消的较长任务。项目中持续发布目标位置通常适合话题，而任务执行还需要明确完成和失败反馈。

### 013｜现场怎样检查目标位姿话题？

**答：**先看话题是否存在，再检查消息类型、发布订阅端和实际数据，最后测接收频率。还要读 `frame_id`、时间戳和单位语义，不能因为出现三个坐标数值就判断结果正确。[ROS2 话题工具][ros-topics]

```bash
ros2 node list
ros2 topic list -t
ros2 topic info /nexus/target/pose --verbose
ros2 topic echo /nexus/target/pose --once
ros2 topic hz /nexus/target/pose
```

### 014｜★ 话题能看到，但订阅不到数据，按什么顺序排查？

**答：**先确认发布端确实在发送，再核对话题名、消息类型和 QoS；跨机器时继续查 domain、网络与发现配置。若消息已经到达进程但业务不更新，再检查回调是否被阻塞。话题可见只说明发现了通信实体，不等于消息已经成功交付。

### 015｜`ROS_DOMAIN_ID` 是干什么的？

**答：**它用于把同一网络上的 ROS2 通信参与者划分到不同逻辑域。需要直接发现彼此的节点应使用一致的 domain；不同小组可以采用不同 domain 减少干扰。但 domain 相同不是通信成功的充分条件，还要满足网络、类型和 QoS 等要求。[ROS Domain ID][ros-domain]

### 016｜★ 为什么 WSL 本机通信成功，换成树莓派就失败？

**答：**跨机器多了网络接口、路由、防火墙和 DDS 发现条件。要先确认 WSL 使用的网络模式，再检查 `ROS_LOCALHOST_ONLY`、domain 和组播可达性。`ping` 通只能证明部分网络连通，不能证明 DDS 正常。支持条件满足时可评估镜像网络，但不能假设所有 WSL 都已启用。[Microsoft WSL 网络说明][wsl-network]

### 017｜DDS 和 RMW 分别是什么？是不是必须两边完全一样？

**答：**DDS 是 ROS2 常用的底层通信技术，RMW 是 ROS2 对中间件的适配接口。不同实现可能互通，但不能把跨实现兼容性当成未经测试的保证。为缩小排障范围，可以先固定相同实现与配置，再单独验证其他组合。[ROS 中间件说明][ros-rmw]

### 018｜图像消息为什么有时选择 Best Effort，而不是 Reliable？

**答：**图像处理常更关注新鲜数据。网络拥塞时，等待旧帧重传可能增加延迟，所以传感器数据配置常采用 Best Effort 和较小队列。Reliable 适合重视交付完整性的场景，但不等于低延迟或硬实时，应该按用途选择。[ROS2 QoS][ros-qos]

### 019｜★ QoS 不兼容具体会出现什么情况？

**答：**例如发布端只提供 Best Effort，而订阅端要求 Reliable，这种可靠性组合不兼容。反过来，Reliable 发布端可以匹配 Best Effort 订阅端。发现节点却收不到数据时，应逐项核对可靠性和持久性等策略，不能只改队列长度。[QoS 兼容表][ros-qos]

### 020｜★ `use_sim_time` 和 `/clock` 是什么关系？

**答：**节点启用 `use_sim_time` 后，ROS 时间可由 `/clock` 提供。这样仿真暂停、加速或回放时，各节点能使用同一套时间。若部分节点使用系统时间、部分使用仿真时间，时间比较和 TF 查询就可能失效；没有有效时钟时也不能假装时间已经正常推进。[ROS2 时间设计][ros-time]

### 021｜为什么不能在收到图像后，直接把当前时间写进消息？

**答：**收到图像的时间包含网络、队列和处理延迟，通常不等于曝光或采样时间。若拿接收时刻的无人机位姿去配较早的图像，运动时会产生额外误差。应保留采样时间，记录时钟来源，并把采集时间和处理完成时间分开。

**追问要点：**简单平移条件下，时间误差引起的位置偏差可粗估为 `v × Δt`；转动还会引入视线变化。

### 022｜相机和 UWB 频率不同，怎样同步？

**答：**先确认两路时间戳处于同一时间基准，再按图像采样时刻关联 UWB 或平台状态。允许插值的状态可以插值，原始异步观测也可以保留各自时间进入估计器。近似同步只按时间戳配对，不能修复设备时钟本身的偏移，容差也要结合运动速度设置。

### 023｜★ `/tf` 和 `/tf_static` 的区别是什么？

**答：**`/tf` 用于随时间变化的变换，`/tf_static` 用于固定关系。相机刚性安装在机体上，其标定外参可以是静态关系；无人机在地图中的位姿随飞行变化，必须动态更新。把 `map → base_link` 发布成静态变换，会把运动平台错误地固定住。[tf2 官方教程][ros-tf]

### 024｜★ 从相机看到目标，到地图中的目标位置，坐标链怎么写？

**答：**需要无人机在地图中的位姿、相机相对机体的外参，以及目标相对相机的位姿。统一变换方向后依次相乘，不能把不同坐标系中的位置向量直接相加。

```text
约定 T_A_B 将 B 系坐标变换到 A 系：
T_map_target = T_map_base × T_base_camera × T_camera_target
```

**追问要点：**各变换应对应同一观测时刻；UWB 单标签距离一般只约束位置，不能独自提供机体完整朝向。

### 025｜TF 报 extrapolation error 时怎么处理？

**答：**先看请求时间是否早于或晚于已有变换缓存，再查传感器时间、平台位姿发布时间和 `use_sim_time` 是否一致。还应检查变换链是否完整。直接改成“总取最新 TF”可能掩盖时间错配，特别是在无人机运动时，不能把不报错当成定位正确。

### 026｜★ 项目为什么同时有 ROS1 和 ROS2？不是说直接使用 ROS2 吗？

**答：**ROS2 是自研算法与应用层，厂商飞控相关 ROS1 代码属于硬件兼容层。仿真链路可以直接接 ROS2，实机数据仍需通过明确通道传入。是否使用通用 bridge 或项目适配器，要看消息类型和设备接口；“仿真直接接 ROS2”不能推出“所有硬件都原生支持 ROS2”。

### 027｜相机接入 ROS2，除了图像还能缺什么？

**答：**还需要与当前分辨率匹配的相机内参、畸变参数、采样时间和光学坐标系。图像编码也要明确，例如 RGB、BGR 或灰度；转换为数组时不能默认通道顺序。只有像素数据，没有这些几何与时间信息，后端仍可能得到错误位姿。

### 028｜为什么把参数和多个节点写进 launch，而不是手动逐个运行？

**答：**launch 便于一致地启动节点、加载参数、设置命名空间和重映射，减少不同人员启动配置不一致的问题。算法阈值可以通过参数管理，但参数名称、默认值和实际生效值必须可查。保存一个参数文件，也不等于现场节点已经使用了它。[ROS2 参数工具][ros-params]

### 029｜模型推理很慢，会怎样影响 ROS2 回调？

**答：**如果耗时推理和其他回调共享受限的执行线程，接收、定时器或状态发布可能被拖延。可以把推理与采集解耦，或合理使用执行器和回调组，但多线程不会自动让模型更快。应先测队列积压与各阶段耗时，再决定怎样拆分。[ROS2 执行器][ros-executors]

### 030｜★ rosbag 在你们的复现流程中有什么作用？

**答：**它保存带时间信息的消息流，让不同算法可以重复处理相同输入。录包时要覆盖必要的传感器、相机信息和坐标变换，并记录参数、代码版本与标定版本。回放还需核对时钟和 QoS；能播放出来不等于消息完整，更不等于实验完全可重复。[ROS2 录制与回放][ros-bag]

## 二、UWB 定位算法复现（031–040，共 10 题）

### 031｜★ UWB 定位的观测量和未知量分别是什么？

**答：**在这里讨论的距离定位模型中，观测量是标签到各基站的距离，已知量是基站坐标，未知量是标签位置。不是直接把某个测距值当成 x、y 或 z。每条距离都提供一个球面约束，多条约束共同确定位置。

```text
第 i 个基站：a_i；标签位置：p；测得距离：d_i
d_i = ||p - a_i|| + ε_i
```

### 032｜★ 三维定位用三个基站就一定能得到唯一位置吗？

**答：**不能保证。三个球面在一般情况下可能产生两个镜像交点，需要额外条件消除歧义。已知绝对距离、没有额外未知偏置时，通常采用至少四个几何分布合适的基站。即使数量足够，基站共面或分布狭窄也可能使某些方向非常不稳定。

**追问要点：**这里讨论的是距离已知的定位模型；不能把这个数量结论直接搬到含未知时钟偏差的其他测量模型。

### 033｜多边测量为什么可以写成最小二乘问题？

**答：**有噪声时，各距离球面通常不会精确交于一点，所以要找一个位置，使预测距离与实测距离的总体差异最小。测距质量不同还可以加权，但权重需要由噪声模型或实验估计支持，不能随意调整到结果好看。

```text
p* = argmin_p Σ_i w_i (||p - a_i|| - d_i)²
```

### 034｜泰勒级数定位怎样迭代？为什么依赖初值？

**答：**它在当前位置估计附近把非线性距离方程做一阶近似，求出位置增量，再更新并重复。初值离真实位置太远时，局部线性近似可能不准确；几何退化也会使增量不稳定。因此要检查初始化、收敛条件和异常样本，不能只说“迭代越多越准确”。

**追问要点：**距离对位置的雅可比为 `(p-a_i)^T / ||p-a_i||`，每行表示该基站对位置变化的敏感方向。

### 035｜★ EKF 用什么办法把历史信息用起来？

**答：**EKF 先根据运动模型预测状态和不确定度，再用新观测修正。例如状态可以包含位置与速度，观测模型可以采用到基站的距离。过程噪声 Q 描述模型的不确定性，测量噪声 R 描述观测的不确定性；二者失配时，滤波可能滞后或抖动。

```text
创新：r = z - h(x_pred)
增益：K = P_pred Hᵀ (H P_pred Hᵀ + R)⁻¹
更新：x = x_pred + K r
```

**追问要点：**这是测距式 EKF 的说明。具体复现是直接输入测距，还是先解算位置再滤波，必须核对相应脚本，不能混称。[UWB 五算法源码入口][uwb-five]

### 036｜PPT 说 UKF 精度高于 EKF，这是不是普遍结论？

**答：**不是。EKF 通过一阶线性化传播状态，UKF 用 sigma 点近似非线性变换后的统计量。UKF 在某些非线性条件下可能更合适，但表现仍取决于运动模型、噪声、初值和参数。答辩时只能说本组测试中哪个结果更好，不能给出无条件排名。

### 037｜图优化比单帧解算多利用了什么信息？

**答：**滑动窗口方法把一段时间内的状态和约束一起求解。除了当前测距，还可以加入运动关系或先验，让局部异常不至于完全决定单帧结果。窗口增大会增加变量和求解开销，实际收益需要通过窗口大小、延迟和精度的对比验证。[图优化开源项目][uwb-graph]

**追问要点：**“使用鲁棒核”属于具体配置，应查看本次运行是否启用，不能由“图优化”三个字自动推出。

### 038｜遇到非视距和异常测距，算法怎样处理？

**答：**非视距可能产生带偏差的测距，不能只当成均值为零的小噪声。可以结合测距质量、残差和多基站一致性进行降权或剔除，再观察位置是否恢复。鲁棒损失能够减轻部分外点影响，但大范围遮挡或基站几何不足时，仍应报告定位质量下降。

### 039｜★ UWB 结果页中，最值得讲的数字是什么？

**答：**按 PPT 第 12 页，图优化的三维 RMSE 约 0.119 米，即 11.9 厘米；两种基础方法约 0.263 米，即 26.3 厘米。图优化平均耗时约 1.97 毫秒，更高的计算量换来了本组数据上更低的误差。这不等于实机已经达到该精度，也不代表所有场景都最优。

### 040｜怎样确认六种 UWB 算法比较公平，尖峰又说明什么？

**答：**要统一锚点、原始测距、轨迹、单位和评价帧，并记录各自初始化与参数。尖峰可能来自初始化、异常测距或求解失败，需要回看原始帧。表中两种方法指标相同，也应核查是否实际使用了不同求解流程，不能仅凭名称认为比较已充分完成。

**追问要点：**PPT 的 100 帧比较尚缺本次能对照的完整运行记录；已有 E004 是另一批 UWB 仿真，不能替代它。

## 三、GDR-Net 论文与复现（041–055，共 15 题）

### 041｜★ GDR-Net 是什么论文，解决什么问题？

**答：**GDR-Net 是 CVPR 2021 的单目六维物体位姿估计工作。输入是目标的 RGB 图像信息，输出是物体相对相机的旋转和平移。六维指三维位置和三维朝向的自由度；它不直接输出无人机在地图中的完整导航状态。[GDR-Net 论文][gdr-paper]、[作者仓库][gdr-repo]

### 042｜★ “几何引导直接回归”是什么意思？与传统 PnP 有什么区别？

**答：**网络先学习图像像素与物体三维结构之间的中间表示，再由可学习的位姿头输出结果。传统路径则把对应点交给几何 PnP 求解器。GDR-Net 的关键是用几何监督帮助位姿学习；项目中另行接 OpenCV PnP 的适配器，应明确称为后处理路径，不能等同于原始可微回归头。[作者模型实现][gdr-code]

### 043｜你们复现时用了什么骨干和输入尺寸？与原论文完全一致吗？

**答：**PPT 展示了 ResNet-18、256×256 的 ROI 输入与 64×64 的稠密输出。当前训练脚本也能看到这些配置，以及 ConvPnPNet 位姿头。但这是项目的裁剪配置，不能称为原论文所有实验的标准设置；要说明某次结果具体用了什么，还需要对应运行配置和权重。

### 044｜★ 训练 GDR-Net 只需要检测框吗？

**答：**不够。按这里的几何监督训练方式，还需要目标模型、相机内参、目标位姿，以及掩膜、稠密物体坐标等可生成或提供的监督信息。检测框只告诉网络目标大致在哪里，不能唯一确定每个像素对应的物体三维点，更不能直接给出完整旋转标签。

### 045｜目标裁剪并缩放以后，相机内参需要怎样处理？

**答：**像素坐标变了，几何关系也必须同步更新。可以使用裁剪后的内参，也可以把预测点还原到原图，再使用原内参；两种约定都可以，但不能混用。补边、非等比缩放等操作也要计入变换。

```text
简单裁剪原点为 (x0,y0)，缩放为 (sx,sy)：
fx' = sx·fx，fy' = sy·fy
cx' = sx·(cx-x0)，cy' = sy·(cy-y0)
```

### 046｜稠密 XYZ、mask 和 region 分别有什么作用？

**答：**XYZ 表示目标表面的物体坐标，不是像素在地图中的坐标；mask 用来区分目标与背景；region 对表面区域提供额外几何监督。归一化 XYZ 进入几何求解前，还要恢复实际物体尺度并核对单位，否则可能产生很大的尺度误差。[GDR-Net 模型实现][gdr-code]

### 047｜★ `allo_rot6d` 中的 6D，和“六维位姿”是同一个意思吗？

**答：**不是。六维位姿描述位置与朝向的自由度；`rot6d` 是用六个数参数化旋转，最后要转换成合法旋转矩阵。`allo` 表示一种结合目标视线方向的旋转表达，需要再转换为相机参考下的旋转。不能把这六个输出直接当成 x、y、z 和三个角度。

**追问要点：**检查转换后是否满足 `RᵀR≈I`、`det(R)≈1`；具体表达由模型配置和转换实现决定。[GDR-Net 模型实现][gdr-code]

### 048｜单张 RGB 没有直接测距，GDR-Net 怎么能输出米制平移？

**答：**它利用了已知物体的尺度、训练数据和图像几何信息，并非仅凭任意未知物体的一张照片就消除了尺度歧义。目标尺寸、内参或数据分布变化都可能使深度估计偏移。当前项目后续几何方案又规定深度不直接采用网络回归值，应与这次历史基准分开说明。

**追问要点：**还原到原图的目标原点投影为 `(u,v)`，其光轴深度为 `z` 时，针孔模型给出 `x=(u-cx)z/fx`、`y=(v-cy)z/fy`。这里仍需要可靠的 z，不能靠这个公式凭空获得尺度。

### 049｜★ Loss 从 4.5 降到 0.5，能证明定位精度已经很好吗？

**答：**只能说明展示的训练目标在下降，不能直接换算成厘米精度。总损失由多个分量和权重组成，即使训练收敛，也可能过拟合或存在评估口径问题。还要在独立数据上检查平移、旋转、失败率和不同目标的表现，尤其要区分真值框与检测框条件。

### 050｜老师问学习率、batch size、优化器和训练轮数，应该怎样回答？

**答：**应以产生该图的运行配置为准。当前已读训练脚本默认学习率为 0.001、batch size 为 16、训练 200 轮，实际训练循环使用 AdamW。但命令行可以覆盖默认值，当前代码也可能晚于 PPT 的实验，因此这些参数不能直接冒充历史运行参数。[当前训练脚本][local-gdr-train]

**代码细节：**该训练循环使用 `weight_decay=1e-5`，并把梯度范数裁剪到 10；构建配置中的 RMSprop 并不是此循环实际调用的优化器。排查时应沿执行路径确认，不能只搜索到一个优化器名称就作结论。

**追问要点：**同时准备 checkpoint、代码提交、随机种子、训练集划分和实际命令，才能把曲线与具体实验对应起来。

### 051｜★ GT ROI 和 YOLO ROI 的对比为什么重要？

**答：**GT ROI 使用真值框，能较少受到检测错误影响；YOLO ROI 更接近检测器接入后的使用条件。固定网络、图像和评价方式，只更换框来源，才能分析检测环节带来的损失。要进一步证明框偏移是主要原因，可以控制中心偏移、尺度变化和漏检分别做实验。

### 052｜对称物体为什么会让旋转误差评价变复杂？

**答：**某些物体旋转后外观和几何仍等价，直接比较一个指定旋转真值，可能把等价姿态判成大错。应根据模型对称信息采用相应的姿态或表面误差评价，同时说明不可观测的旋转方向。对称性处理不同的两组数字，不能直接并列比较。

### 053｜★ GDR-Net 的 7.75 厘米、20.33 厘米和 23.24 度分别代表什么？

**答：**按 PPT，前两个是 YOLO ROI 条件下平移误差的中位数和 P95，后一个是旋转误差中位数。中位数描述典型样本，P95反映尾部情况；它们不等于平均值，也不代表全部样本都在阈值内。这些是 PPT 的阶段性展示值，对应 E012 完整记录仍需补齐。

### 054｜能把之前十类目标的模型直接用于现在三目标的 RRD 数据吗？

**答：**要先核对类别、物体模型、尺寸、相机参数和标注结构是否一致。项目索引中提到的 RRD 检测数据批次只有框信息，不能直接承担原先的稠密几何监督。目标数量减少也不意味着迁移更容易；必须明确数据批次和模型适用范围。

### 055｜★ 怎样表述“我们复现了 GDR-Net”才准确？

**答：**要说清复现到哪一层：官方模型能运行、在自有数据上训练、完成指定条件评估，还是复现了论文基准。项目还有训练链路和稠密输出接 PnP 的适配链路，它们不能混称。缺少同数据、同指标和可追溯运行时，不应说已经完全复现论文性能。

## 四、SuperPoint 与固定地图定位（056–070，共 15 题）

### 056｜★ SuperPoint 是定位算法还是特征算法？

**答：**SuperPoint 是 CVPR Workshops 2018 的兴趣点检测与描述工作，本身输出关键点和描述子。它不直接给出地图位置，也不包含完整 SLAM 所需的建图和状态估计。PPT 展示的位置结果来自我们组合的固定地图定位链路，不能全部归为 SuperPoint 网络的直接输出。[SuperPoint 论文][sp-paper]、[作者仓库][sp-repo]

### 057｜SuperPoint 的共享编码器和两个输出头怎样工作？

**答：**共享编码器提取图像特征，检测头预测关键点位置，描述子头描述各位置的局部外观。作者发布的模型中，检测头在低分辨率网格上输出 65 个通道，对应 8×8 个位置及一个无关键点类别；描述子为 256 维。后处理后得到可匹配的点和向量。[作者网络代码][sp-code]

### 058｜★ SuperPoint 的“自监督”体现在哪里？

**答：**论文先利用合成图像训练基础检测器，再对真实图像施加已知单应变换，把检测结果映射回来并聚合，生成更稳定的伪标签，这就是 Homographic Adaptation。它减少了手工标注关键点的需要，但不意味着训练过程完全没有监督信号。[SuperPoint 原论文][sp-paper]

### 059｜你们重新训练了 SuperPoint 吗？

**答：**按 PPT 的复现说明，使用的是官方预训练特征前端，重点工作在固定地图、检索、匹配和 PnP 的接入与评价。介绍论文训练方法，是解释其原理，不能说成我们已经在自有数据上重新完成了全部自监督训练。

### 060｜538 个关键点是固定输出吗？点越多越好吗？

**答：**不是固定数量，它受画面纹理、分辨率、阈值和非极大值抑制影响。非极大值抑制用于避免相邻位置出现大量重复响应。有效且分布合理的点更有价值，增加弱纹理或重复纹理上的点，可能只会增加误匹配和计算量。[SuperPoint 后处理实现][sp-code]

### 061｜★ 为什么在线定位先做 Top-10 检索？

**答：**参考地图有 550 帧，逐张做精细匹配开销较大。先用低成本的外观比较筛出 10 个候选，再进行局部匹配，可以减少后端工作量。代价是正确参考帧可能没有入选，所以要在验证集上比较候选数量与召回率，10 不是通用最优值。

### 062｜距离阈值、ratio test 和双向最近邻各管什么？

**答：**距离阈值拒绝外观差异过大的描述子；ratio test 比较最佳与次佳匹配，排除不够明确的对应；双向最近邻要求双方互相选择，减少单向误配。PPT 中的 0.70 和 0.85 属于当前配置，应结合描述子归一化和验证结果解释，不能认为所有图像都适用。

### 063｜★ z-depth 和沿视线距离有什么区别？为什么会影响精度？

**答：**z-depth 是三维点沿相机光轴的坐标，沿视线距离是相机到该点的欧氏距离。两者在图像边缘差异更明显。反投影公式必须与数据语义一致，否则三维地图会发生系统性变形。PPT 强调的是其数据处理中的语义修正，不能推广为所有传感器都输出同一种深度。

```text
q = K⁻¹[u,v,1]ᵀ
若 D 为 z-depth：P_camera = D·q
若 R 为欧氏距离：P_camera = R·q / ||q||
```

### 064｜从参考图的一个关键点，怎样得到三维地图点？

**答：**先取与该像素对应的有效深度，用内参反投影到参考相机坐标系，再用该参考帧的已知位姿变换到地图坐标系。要保证深度、图像和位姿来自同一时刻，深度边界上的像素还可能落到背景。参考帧位姿误差也会进入地图，进而影响在线定位。

### 065｜多参考帧聚合有什么好处，为什么还要去重？

**答：**不同参考帧提供互补视角，可以增加有效三维对应。但同一个查询关键点可能与多个参考点匹配，如果全部保留，就可能重复计算同一信息，甚至引入冲突。PPT 的做法是为同一查询点保留最合适的三维对应，再送入几何求解。

### 066｜★ Fundamental RANSAC 和 PnP RANSAC 是同一个步骤吗？

**答：**不是。前者用两张图的二维对应检查极线几何一致性；后者用三维地图点与查询图像点估计相机位姿。通过前一道检查，不代表三维关联一定正确。两类阈值、输入与残差含义不同，记录实验时要分别说明。[OpenCV PnP 说明][opencv-pnp]

### 067｜★ PnP 输出的平移向量，是相机在地图中的位置吗？

**答：**通常不能直接这样读。以 OpenCV 的约定为例，若输入是地图三维点，输出满足 `P_camera = R·P_map + t`。相机中心在地图中的坐标是 `-Rᵀt`，还需要对姿态取逆。把 `t` 直接发布成地图位置，是常见的方向错误。[OpenCV 位姿约定][opencv-pnp]

### 068｜AP3P 为什么还需要 RANSAC 和后续迭代？

**答：**最小求解器能快速生成候选，但匹配中存在外点，且少量点容易受噪声影响。RANSAC 通过反复采样寻找一致的候选，再用更多内点做迭代细化。还要检查点的空间分布；近共线等退化结构可能使位姿不稳定，内点多也不能保证条件良好。[OpenCV 求解方法][opencv-pnp]

**追问要点：**平面点集有可用的专门求解方法，不能简单说“共面就无法 PnP”；应分析具体几何和多解问题。

### 069｜★ 为什么验证集 RMSE 为 5.27 厘米，测试集反而只有 2.94 厘米？

**答：**验证集 8 帧、测试集 30 帧，样本数量和场景难度不同，测试误差更低并不自动矛盾。但也不能据此证明模型泛化很好。需要检查采样覆盖、参考图重叠和是否重复调参。PPT 的 30 帧全部有效，只代表这 30 帧的结果，不保证任意新场景都有效。

### 070｜★ 特征提取只要 18.62 毫秒，为什么系统只有 2.42 赫兹？

**答：**18.62 毫秒是特征前端的展示耗时，完整链路还包括检索、匹配、三维关联、聚合和 PnP。PPT 的全流程平均耗时约 413.79 毫秒，取倒数约为 2.42 次每秒。优化前要做分阶段计时，不能把前端速度当成完整定位速度。

## 五、LightGlue 论文与复现（071–080，共 10 题）

### 071｜★ LightGlue 是哪篇论文？在系统中承担什么任务？

**答：**LightGlue 是 ICCV 2023 的局部特征匹配工作，用于判断两张图中哪些点相互对应。它既不是目标检测器，也不直接输出三维位置。答辩时应将其放在匹配阶段介绍，不能沿用旧稿中把会议写成 CVPR 的说法。[LightGlue 作者仓库][lg-repo]

### 072｜SuperPoint 和 LightGlue 的接口怎样衔接？

**答：**先用 SuperPoint 分别提取两张图的关键点和描述子，再把这些信息传给对应的 LightGlue 模型，得到匹配索引或分数。要核对坐标是否已还原到原图、张量形状和设备是否一致，并选择与特征类型对应的预训练权重。[LightGlue 输入输出实现][lg-code]

### 073｜Self-Attention 和 Cross-Attention 分别解决什么？

**答：**Self-Attention 让一张图中的特征利用同图其他点提供的上下文；Cross-Attention 让两张图之间交换信息，判断对应关系。这样做不只比较两个独立描述子的距离，还利用它们在整组特征中的关系，但依然可能在重复纹理等条件下出错。[LightGlue 论文][lg-paper]

### 074｜★ LightGlue 的自适应深度和宽度是什么？

**答：**深度自适应是根据匹配状态提前结束后续层计算；宽度自适应是逐步裁剪不值得继续处理的点。容易的图像对可以少算一些，困难样本可能需要更多计算。它调整的是网络推理工作量，不是已经完成了项目系统级的传感器自适应融合。[LightGlue 官方配置说明][lg-repo]

### 075｜匹配置信度高，就一定匹配正确吗？阈值越高越好吗？

**答：**置信度是模型判断，不是真实几何关系的保证。提高阈值可能减少弱匹配，但也可能删掉求解所需的有效点；降低阈值则可能增加外点。应该在验证集上看几何内点、空间覆盖和最终位姿，不能只追求匹配数量或平均分数。[LightGlue 匹配过滤实现][lg-code]

### 076｜★ 为什么 LightGlue 后面还要做 RANSAC？

**答：**网络给出外观对应，RANSAC 再检查这些对应是否满足选定几何模型。模型、阈值和成功条件都要明确。项目匹配统计采用内点门槛，并不意味着达到该门槛就已经恢复了可用三维位姿；两者需要分开验证。

### 077｜91.6% 成功率和 0.630 内点比分别怎么计算？

**答：**PPT 中 174 对成功除以 190 对，约为 91.6%。单对内点比是几何验证通过的点数除以该对匹配数；汇总时，还要区分“各对比例的平均”和“总内点数除以总匹配数”。这两种汇总可能不同，应以生成本页的统计脚本为准。

**追问要点：**20 张图不重复两两配对得到 `20×19÷2=190` 对；这些图像对共享图像，不能当成 190 次完全独立采样。

### 078｜★ 论文强调速度，你们为什么测到约 2.1 秒？

**答：**需要比较硬件、关键点数量、图像尺寸、推理配置，以及计时是否包含特征提取和几何验证。PPT 展示的是该实验配置的整体表现，不能直接归因为网络本身慢。优化时应先分段测量；约 0.47 赫兹只能说明当前更新速度，不能证明满足无人机实时定位要求。

### 079｜LightGlue 的匹配更好，最终定位就一定更准吗？

**答：**不一定。位姿还取决于三维地图质量、点的几何分布、候选检索和求解器。更多匹配可能集中在同一平面或重复结构上。公平比较应固定特征、地图、查询集和评价口径，尽量只替换匹配后端，再比较最终误差、成功率与耗时。

### 080｜★ 怎样把 LightGlue 的复现结果交给别人重新跑？

**答：**要提供上游版本、权重、输入图像清单、配对规则、参数、设备和完整命令，并导出每对结果。当前仓库有一份 5 帧、10 对的 E007 记录，而 PPT 是 20 帧、190 对，二者不是同一批次。因此需要补齐 PPT 对应记录，不能用旧记录替代新版数字。

## 六、实验、系统、协同与部署（081–100，共 20 题）

### 081｜★ 四类方法的结果为什么不能直接排成一个精度榜？

**答：**它们的任务与输出不同。UWB 定位标签及无人机平台，GDR-Net 估计外部目标相对相机的位姿，固定地图 SuperPoint 链路恢复相机位姿，LightGlue 输出匹配关系。只有定位对象、数据条件和指标相同时，数值才具备直接比较意义。

| 方法 | 本 PPT 中的主要输出 | 不能直接替代的结果 |
|---|---|---|
| UWB | 标签/平台三维位置 | 无人机完整朝向、外部目标位姿 |
| GDR-Net | 目标相对相机的位姿 | 地图坐标下的目标位姿 |
| SuperPoint + 固定地图 + PnP | 相机在地图中的位姿 | 外部目标位姿 |
| LightGlue | 图像间局部点对应 | 三维位置与定位精度 |

### 082｜参考集、验证集和测试集为什么要分开？

**答：**参考集提供离线地图，验证集用于选择参数和方案，测试集用于在配置确定后评价。PPT 的 550 帧在这条链路中是建图参考，不应直接称为重新训练 SuperPoint 的训练集。若反复根据测试集调整阈值，测试集就不再是独立检验。

### 083｜★ 在线只输入 RGB，就能证明没有数据泄漏吗？

**答：**还不能。除了检查网络输入，还要看检索、过滤和参数选择有没有读取查询帧真值或深度。固定地图允许使用预先建立的参考信息，但必须说明地图来源，并检查测试图是否与参考图重复。离线地图使用真值辅助，与在线查询读取答案，是不同问题。

### 084｜CARLA 固定步长 0.05 秒，是否就代表程序每秒能跑 20 帧？

**答：**它表示每个仿真步推进 0.05 秒，即每个仿真秒有 20 步；实际墙钟时间可能更长或更短。同步模式还需要明确由谁触发 tick，并根据帧号配齐传感器数据。不能用仿真步长直接证明采集程序或定位算法具有 20 赫兹实时性能。[CARLA 同步与步长][carla-sync]

### 085｜地图 SHA256 一致、130 个生成点，分别能证明什么？

**答：**校验值一致说明被比较的文件内容一致，生成点数量说明该地图提供的采样或生成位置规模。它们有助于确认环境与数据来源，但不能证明物理模型完全真实、噪声设置正确或定位精度可靠。这些结论需要各自的测试证据。

### 086｜★ 仿真里得到厘米级结果，迁移到实机最容易在哪些地方失效？

**答：**真实图像有光照变化、运动模糊、畸变和遮挡，实机还有测距偏差、标定误差、时间偏移和通信延迟。仿真中的固定地图或准确位姿也不一定能在现场获得。应先建立可测真值的实机测试，再逐项比较误差来源，不能直接沿用仿真精度。

### 087｜棋盘格标定具体解决什么？标定一次就够了吗？

**答：**它用于估计相机内参和畸变参数，使像素与视线的关系更准确。采样应覆盖不同位置和倾角，尤其是图像边缘。分辨率、裁剪模式或镜头状态改变后，需要检查原参数是否仍适用；去畸变后也要使用与新图像一致的内参，避免重复校正。

### 088｜相机内参、相机外参和 UWB 基站测量是一回事吗？

**答：**不是。内参描述相机投影，机体到相机的外参描述安装位置和朝向，UWB 基站测量确定各基站在地图中的位置。任何一项误差都可能传到最终目标坐标。仿真配置里的安装值与基站坐标，不应直接当成实机标定结果。

### 089｜★ RMSE、MAE、P95 和可用率为什么要一起报告？

**答：**MAE 描述平均位置误差，RMSE 对较大误差更敏感，P95 描述尾部，可用率说明多少帧成功输出。只报告成功帧的 RMSE，可能掩盖大量失败；把失败帧记成零误差更不合理。应同时交代参与统计的样本数和失败处理方式。

```text
e_i = ||p_est,i - p_gt,i||
MAE = mean(e_i)
RMSE = sqrt(mean(e_i²))
可用率 = 有效输出帧数 / 应评价帧数
```

### 090｜测推理时间有哪些容易让结果失真的地方？

**答：**首次加载、预热、磁盘读取、CPU/GPU 数据搬运和 GPU 异步执行都可能影响计时。应分别说明纯模型耗时与端到端延迟，用一致的输入和预热规则重复测量，并报告中位数或尾部耗时。GPU 计时需要使用适当同步或设备计时方式，不能只测任务提交时间。

### 091｜为什么把数据存储从树莓派移到地面服务器？

**答：**PPT 展示的思路是减少机载端高频落盘带来的存储与内存压力，让机载端集中承担采集和传输。但压力也会转移到网络，所以仍要测传输带宽、丢包、排队和服务器写盘能力。架构调整后需要持续运行验证，不能仅凭流程图说问题已经彻底解决。

### 092｜★ UWB 和视觉融合，是把两个位置取平均吗？

**答：**首先要确认两路是否描述同一个对象、同一时刻和同一坐标系。若一个是无人机位置，另一个是目标相对相机位置，就必须先建立测量关系，再参与估计。即使是同一对象，也应考虑不确定度、观测相关性和异常情况，直接平均缺乏这些依据。

### 093｜后续方案为什么强调几何深度？这与 GDR-Net 复现冲突吗？

**答：**不冲突，前者是项目基于误差分析作出的后续路线选择，后者是已有基准。多视角几何需要可靠的相对运动与足够视差，支撑面约束需要可信的平面高度；它们也有前置条件。项目当前方案不直接消费网络回归深度，但效果还要由对应实验验证。

### 094｜Chain A、B、C 的区别怎样用一句话说明？

**答：**按 PPT 的规划，A 侧重正常观测下的精度，B 侧重遮挡、模糊和外点条件下的稳定性，C 根据观测质量调整组合。真正需要验证的不是给三条链起名字，而是同一输入下的误差、失败、切换和恢复行为，尤其要避免切换时位置跳变。

### 095｜★ CARLA、ROS 机体和相机坐标系最容易混淆什么？

**答：**CARLA/Unreal 的轴向和手性与项目采用的 ROS 右手坐标不同；ROS 机体通常按前、左、上，相机光学坐标按右、下、前。转换要同时处理位置与旋转，不能只给一个坐标分量改符号。单位也要统一，尤其注意米、厘米、毫米和角度制。

**追问要点：**用单位轴、已知位姿和往返变换检查，而不是凭三维图“看起来方向正确”。

### 096｜新版 PPT 中，三个小组怎样形成协同？

**答：**NEXUS 提供无人机与目标定位能力，无人车组负责建图和导航，协同组负责信息传递与任务下发。合并联调应把目标坐标、参考坐标系、时间、任务编号和执行状态说明清楚。各组单独能运行，只是联调的起点，还不等于完整任务已经成功执行。

### 097｜桌面 GPU 上能跑，树莓派部署主要难在哪里？

**答：**树莓派的计算平台、内存带宽和加速支持与桌面 NVIDIA GPU 不同。要先核对依赖能否运行，再测完整链路的延迟、内存和持续温度。压缩模型、减少候选或分配地面计算都需要实测比较，不能把桌面耗时直接作为机载性能。

### 098｜★ `/nexus/target/pose` 发布成功，就能直接让无人机飞过去吗？

**答：**目标位姿是感知结果，通常还不是可直接执行的控制指令。任务层需要处理目标有效性、坐标转换、到达位置和运动约束，控制层再执行。项目首版也不把回传飞控作为所有演示的必选项；PPT 中的闭环箭头应按后续验证计划解释。

### 099｜用了开源算法，你们自己的贡献在哪里？

**答：**可以具体说明数据采集、统一坐标与时间、算法适配、对照评估、误差诊断和系统集成。比如把特征前端接成可评价的固定地图定位链路，属于明确的工程工作。若要主张算法创新，则还需要新的方法设计和消融证据，不能把使用开源模块本身包装成原创算法。

### 100｜★ 如果老师最后问“现在做到哪一步，还差什么”，怎样回答？

**答：**按这份 PPT，我们展示了环境与数据准备、实机基础验证和几类算法的阶段性比较。尚需补齐部分展示数字的运行证据，并完成融合、部署和协同联调的系统评价。下一步优先用固定条件验证精度、延迟、失效与恢复，再说明是否达到项目目标。
