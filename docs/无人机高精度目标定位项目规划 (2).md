# 无人机高精度目标定位方法 —— 项目实施规划书（幻思硬件适配版）

> **赛题对象补充决定（2026-08-18）**：被定位对象是无人机之外的目标，无人机是传感器、通信和计算平台。ROS1/`fcu_core` 只承担幻思硬件兼容，ROS2 承担目标定位、算法比较、坐标转换、评估和演示；`motion_001` 回传飞控降为可选扩展。目标形态、UWB 标签安装、相机视角、坐标系和真值方案在硬件到货后确认。完整边界见 `docs/decisions/2026-08-18_ADR-002_target-localization-scope.md`；本规划后文保留的无人机自定位/回传描述是历史技术路线，不得覆盖该决定。

**项目类型**：FanciSwarm UWB + 视觉融合定位系统（幻思 Mcontroller V7 + 官方 fcu_core ROS 工程）
**团队规模**：5人
**周期**：4周
**精度目标**：核心演示区 ≤ 5cm（视觉可见时），全场景兜底 < 30cm（依据学校提供沙盘的实测特征，5cm 是有充分技术依据的冲刺目标，详见第二节）
**开发模式**：全程 AI-Agent（Claude Code）辅助开发

> **硬件适配结论（2026-08-18）**：本项目采用双 ROS 分层。Ubuntu 20.04 + ROS1 Noetic + 官方 `fcu_core` 作为幻思硬件兼容层，通过 USB `/dev/ttyACM0` 或网络 `192.168.4.1:333` 通信；Ubuntu 22.04 + ROS2 Humble 作为自研算法与展示主线。两侧通过 `ros1_bridge` 或轻量自定义 bridge 连接，不把两套 ROS 混装。FanciSwarm UWB 由 4 个基站和机载 DWM1000 标签组成，位置估计在无人机端分布式完成。官方 `fcu_core` 支持机载电脑和远程主机两种模式，树莓派5 8G可承担 ROS1 硬件侧，视觉和分析可放在 ROS2 外部主机。原规划中与 Nooploop、TDOA 自写解算器和未经验证的视觉输入冲突的表述，以本段和后文修订为准。

**官方资料依据**：幻思 Mcontroller V7 支持 FreeRTOS、MAVLink、USB/串口、SD 日志、内置 EKF 与官方 ROS 工程；FanciSwarm UWB 为四基站本地三维定位，厂商标称精度小于 10cm（实际取决于环境与系统设置）；UM982 GNSS 作为室外/开阔场景的可选高精度来源，不作为沙盘室内主定位源。

## 一、总体技术路线

单一传感器都有各自的天花板，所以整个方案的核心思路不是"选一个最好的算法"，而是**做一套 UWB + 视觉的互补融合定位系统**，让两种技术互相弥补短板：

| 传感器 | 优势 | 短板 |
|---|---|---|
| FanciSwarm UWB（超宽带） | 四基站本地三维定位、飞控端分布式解算、不依赖外部计算机即可工作 | 厂商标称三维精度小于10cm，但受布局、环境和系统设置影响，需实测 |
| 视觉（AprilTag/ArUco + 相机） | 视线内精度可达毫米～厘米级，姿态信息丰富 | 依赖光照与视线，易被遮挡，视场角有限 |

**技术路线**：FanciSwarm UWB 在飞控端提供全局绝对位置，光流/激光测距维持室内飞行稳定；ROS1 通过官方 `fcu_core` 读取飞控状态，bridge 将状态送入 ROS2，视觉在可视范围内提供高精度修正，再按接口表将视觉位姿映射回 ROS1 `motion_001`。第一版不替换飞控内置闭环，先把“官方 UWB → ROS1 → bridge → ROS2 视觉修正 → ROS1 回传 → 演示记录”跑通。

需要明确一个关键认知：幻思官方 UWB 标称三维定位精度小于 10cm，但实际受基站布局、环境和系统设置影响；不能把宣传上限当作实测结论。视觉可见时冲击 5cm，UWB 作为绝对位置基线和视觉丢失时的飞行兜底。若厂商接口只提供已解算位置而不开放原始测距，就不再硬做 LS/Chan/Taylor 五算法比较，而是比较官方 UWB、视觉和视觉回传后的轨迹误差。

## 二、场地实测特征与 5cm 精度冲刺方案

根据学校提供的沙盘实拍照片，这是一个**室内桌面级"十字路口+城市建筑群"沙盘**（有车道、斑马线、红绿灯、树木、储罐建筑模型），周边已经架设了多组三脚架式摄像头/补光灯装置，整体尺度在 3 米量级、层高不高（有吊顶灯槽和大屏幕，头顶空间有限）。这几个客观条件其实都在帮你们，把精度目标从"保底 30cm"上调到"冲刺 5cm"是有扎实技术依据的，不是喊口号：

### 1. 为什么这个场地能支撑 5cm 精度

| 场地特征 | 对精度的影响 |
|---|---|
| 沙盘尺度小（3米量级） | UWB 基站基线短、覆盖冗余度高，多径/NLOS 问题比开阔场地轻得多；相机离目标近，画面里目标占的像素数多，视觉解算精度天然更高 |
| 四周已有多组三脚架摄像头 | 现成的**外部多相机围观阵列**基础设施，比只靠无人机机载单相机的方案精度高一个量级（原理接近简化版动作捕捉系统） |
| 场景内建筑、路口、红绿灯等固定地标丰富 | 天然的高精度标定参考点，不需要额外画网格，标定误差来源更少 |
| 室内环境，光照可控、无风扰 | 排除了室外风扰、强光过曝等干扰视觉解算精度的因素 |

### 2. 落地 5cm 的具体技术手段（按优先级）

**① 视觉系统从"先确认接口"再决定机载/外部方案**
这是把精度从 10~20cm 拉到 5cm 内的**最关键改动**。具体做法：
- 若沙盘三脚架相机能输出同步原始帧，复用它们做外部多相机阵列；否则优先使用幻思视觉套件或树莓派相机做单路验证，不把“已有摄像头”当成可用输入
- 复用沙盘四周已有的三脚架位置时，优先确认相机接口、帧率、时间戳和快门类型，再决定是否购买全局快门相机
- 相机分辨率建议 1080P 起步，条件允许上 4K —— 场地小，相机离目标近，分辨率越高，每厘米覆盖的像素数越多，亚像素级角点检测的精度红利越明显
- 用多相机同步 AprilTag/ArUco 检测 + 三角测量（而不是单相机 PnP）作为冲刺路线；幻思 800 万像素机载相机只有在确认原始视频接口后才进入主链路
- 相机外参标定务必做**多角度、多位置的棋盘格标定**（不少于20组不同角度的标定图像），这是视觉精度的地基，标定草率做，后面算法再好也补不回来

**② UWB 基站部署做几何优化（GDOP优化）**
- 按幻思四基站系统要求部署，先测量并记录基站坐标和高度，再做 GDOP/静态误差对比；不要假定这是 TDOA 或擅自替换 UWB 模块
- 厂商已提供 DWM1000 机载标签和分布式解算，优先验证官方位置输出与基站布局，不把时间花在重复实现厂商协议上

**③ 时间戳与延迟测量**
- 官方 `fcu_core` 当前以 ROS/MAVLink 或 TCP 传递飞控数据；第一版记录飞控时间、ROS 接收时间和视觉采样时间，先测量延迟，再决定是否需要硬件同步，不为尚未观测到的误差提前堆 PTP

**④ 无人机本体与载荷约束**
- 现有 FanciSwarm 已是约80×80×180mm、轴距约113mm 的室内微型平台，不再更换为 Tello/Crazyflie；重点检查树莓派/相机/标签的重量、供电和重心
- 目标物（AprilTag/ArUco标签）贴在无人机顶部或底部，标签尺寸根据相机距离反算，先保证检测稳定，再考虑多标签/多相机

**⑤ 演示验证点结合沙盘已有地标设计**
- 沙盘上的路口中心、建筑物顶角、红绿灯杆基座这些位置本身就是可以精确量出物理坐标的天然标定点/验证点，比额外贴标记点更省事也更有说服力——演示脚本可以设计成"无人机依次悬停在3-4个指定路口/建筑上方，现场读出与真实坐标的偏差"，故事性和可信度都比空场地里飞更强

**⑥ 精度分级要向答辩评委讲清楚**
建议在报告和PPT里明确区分三档精度，不要笼统只说一个数字：
- **视觉可见 + 视觉回传区**：冲刺目标 ≤5cm（必须有实测证据）
- **视觉部分遮挡 + UWB飞控基线区**：以实际 RMSE/CEP95 为准
- **纯UWB飞控区**：厂商标称 <10cm 仅作参考，答辩只报告本项目实测值

这种分级恰恰是"技术严谨"的体现——比一个笼统的"全场5cm"更让人信服，也更贴近工程真实情况。

## 三、四项任务的具体落地方案

### 任务1：幻思官方 ROS 工程与伴随计算机搭建

- **双环境选择**：Ubuntu 22.04 + ROS2 Humble 是项目要求和自研主线；Ubuntu 20.04 + ROS1 Noetic + catkin 是幻思公开 `fcu_core` 的硬件兼容层。两套环境分别运行，不在同一系统内混装。
- 搭建内容：
  - ROS1 导入幻思官方 `fcu_core` 与 `quadrotor_msgs`，先跑通 USB `/dev/ttyACM0` 或网络 `192.168.4.1:333`
  - ROS2 工作空间放 `vision_localization`、`coord_transform`、`fusion_localization`、`viz_dashboard`、`bringup`；ROS1 工作空间只放 `nexus_fcu_bridge`
  - ROS1 使用 `tf`、`roslaunch`、`rosbag`；ROS2 使用 `tf2`、`ros2 launch`、`ros2 bag`、RViz2；树莓派5做 ROS1 轻量节点，视觉/分析放 ROS2 外部主机
  - 第一版允许直接使用厂商飞控内置 UWB/EKF，bridge 负责状态映射，ROS2 负责算法、记录和展示，视觉位姿再映射回 ROS1 `motion_001`

### 任务2：现有定位算法精度比较，选定厘米级方案

这是决定项目上限的关键任务，建议做**系统性对比实验**而不是直接选定一个算法，这本身也是答辩的加分项（体现严谨性）。

**UWB 定位算法候选（以接口能力为前置条件）**：
- 官方 FanciSwarm UWB 位置输出 —— 首要基线，验证四基站布局和环境误差
- 若开放原始四基站测距，再比较 LS/鲁棒最小二乘；不开放时删除 Chan/Taylor/TDOA 伪任务
- UWB 异常时优先记录并评估飞控现有降级行为，不重复实现一套脱离飞控的定位闭环

**视觉定位算法候选（ROS2 实现）**：
- 单目 + AprilTag/ArUco + PnP 解算 —— 部署简单，需已知标签尺寸
- 双目立体视觉 + 三角测量 —— 不依赖已知标签尺寸，精度更稳
- 多固定相机（复用沙盘四周三脚架）+ 多视角三角测量 —— 只有在原始图像可接入时才作为主力。幻思官方视觉套件支持 Jetson Orin + D435/RGB，相机链路优先按实际购买套件确认。**落地工具可继续参考 `mprib/caliscope`，输出先接入 ROS2 `tf2`，再经 bridge 映射为 ROS1 `motion_001`。**

**评估维度**（做成对比表格，是答辩的核心图表之一）：
精度（RMSE/CEP95）、更新频率、抗遮挡能力、算力消耗、部署成本、环境适应性

**建议结论方向**：先用官方 FanciSwarm UWB 位置和飞控内置光流/激光测距跑通稳定飞行，再在 ROS2 中完成视觉并经 bridge 通过 `fcu_core` 回传修正。5cm 只作为视觉链路实测冲刺目标；UWB <10cm 是厂商参考值，最终以本项目静态/动态 RMSE、CEP95 和延迟为准。

### 任务3：坐标转换

- 建立三级坐标系：**传感器坐标系 → 无人机机体坐标系 → 沙盘世界坐标系**
- 标定流程：
  1. UWB 基站坐标高精度测量（用卷尺+已知参考点，或如学校有全站仪则更佳）作为世界坐标系锚点，**基站的具体摆放位置需先跑一版自己写的 GDOP（几何精度稀释度）优化脚本，在沙盘四角范围内搜索几何分布最优的4个点位，而不是随手摆**
  2. 相机内参+外参标定：根据实际相机选择 `caliscope`、OpenCV 或厂商视觉套件工具；不预设 3~4 台相机一定可用
  3. UWB 坐标系与视觉坐标系之间用最小二乘拟合刚体变换（ICP 或 SVD 求解旋转平移矩阵）统一到同一世界坐标系
- ROS2 算法侧将变换注册进 `tf2` 树，ROS1 硬件侧保留 `tf`；bridge 两端明确处理 NED/ENU、机体系、单位和时间戳，视觉位姿按幻思 `fcu_core` 约定回传，避免把轴向弄反

### 任务4：演示应用

- **实时可视化**：ROS2 RViz2 展示 bridge 后的 `/nexus/fcu/odom`、视觉位置和回传后轨迹；不要把“原始 UWB”写成未开放的数据
- **Web Dashboard**（加分项）：使用 ROS2 rosbridge 或直接读取 `ros2 bag`，展示定位坐标、误差曲线和统计
- **精度验证演示**：在沙盘上设置若干已知坐标的标定点，让目标物/无人机依次停靠，现场读出定位误差，用数据说话
- **动态轨迹演示**：无人机按预设路径飞行，实时展示跟踪轨迹与误差热力图

## 六、AI-Agent（Claude Code）全程协助策略

明确各环节让 AI-Agent 发挥最大价值，而不是仅当"代码补全工具"：

1. **脚手架生成**：ROS1 catkin 包、ROS2 ament 包、launch 文件和 bridge 消息适配 —— 先复用 `fcu_core`，只生成真正缺失的胶水代码
2. **算法原型验证**：UWB多种解算算法、EKF/UKF公式推导与代码实现，AI快速生成多版本对比代码
3. **自动调参**：融合算法的过程噪声/观测噪声协方差矩阵，用AI辅助设计贝叶斯优化/网格搜索脚本自动寻优，比人工试参数快得多
4. **调试排障**：坐标变换错位、时间戳不同步等典型 bug，让 AI 分析日志/tf树输出定位问题
5. **文档与答辩材料**：技术报告初稿、PPT大纲、算法对比表格自动生成，团队再做精修
6. **代码审查**：每个模块合并前用 AI 做一轮代码review，统一代码风格、发现潜在bug
7. **数据分析**：ROS1 `rosbag` 与 ROS2 `ros2 bag` 录制数据的自动化精度统计脚本（RMSE/CEP95计算、误差可视化）

> 建议为团队制定一份《AI-Agent使用规范》，明确哪些环节必须人工复核（如坐标标定的物理测量数据、最终精度结论），避免完全依赖AI导致答辩时说不清楚原理。

## 七、精度指标与验证方案

- **核心指标**：
  - RMSE（均方根误差）
  - CEP50 / CEP95（50%/95%置信区间圆概率误差）
  - 最大误差（Max Error）
  - 更新频率（Hz）与延迟
- **验证方法**：
  - 静态测试：在沙盘的路口中心、建筑角点等天然地标上标定 8～10 个已知精确坐标的测试点，逐点采集定位数据统计误差
  - 动态测试：无人机沿预设轨迹（直线、圆形、"8"字"，尽量沿着沙盘车道走）飞行，与规划轨迹做误差对比
  - 遮挡/异常场景测试：人为遮挡视觉标签、制造UWB多径干扰，验证降级机制是否稳定接管
  - 对比实验：分别记录"仅UWB""仅视觉（单相机PnP）""仅视觉（多相机三角测量）""融合后"四组数据，用图表直观证明"多相机方案比单相机方案精度提升多少""融合比单一传感器更稳"（这是答辩的核心说服力图表，也直接对应任务2要求的算法精度比较）
  - **分级精度报告**：按第二节提出的三档（视觉主导区 ≤5cm / 过渡区 8~15cm / UWB兜底区 15~25cm）分别统计并可视化成误差热力图，比单一均值更有说服力

## 八、创新点建议（提升技术优秀度）

1. **自适应融合权重**：融合算法中不用固定协方差矩阵，而是根据UWB测距残差、视觉重投影误差实时估计各传感器置信度，动态调整融合权重
2. **NLOS/遮挡智能降级机制**：设计状态机，当视觉丢失目标时无缝切换到纯UWB模式，UWB出现多径异常时用视觉数据做修正，保证系统连续性而非"掉线"
3. **大胆但受控的回传修正**：不先重写飞控 EKF；直接利用幻思 `fcu_core` 的视觉位姿回传接口，把视觉结果送入飞控位置环，先用真实飞行效果证明改进，再决定是否增加自定义滤波
4. **误差可视化Dashboard**：实时误差热力图，直观展示沙盘不同区域的定位精度分布，体现工程严谨性
5. **多机协同定位（如有多台无人机/多目标）**：UWB网络协同定位，提升整体覆盖精度
6. **多相机外部阵列的置信度加权融合**：只有在多路原始图像真实可用时实施；根据相机观测质量对三角测量结果加权，作为 5cm 冲刺路线，而不是预先承诺的必选复杂度

## 九、风险与应对预案

| 风险 | 应对措施 |
|---|---|
| 幻思官方 `fcu_core` 的公开主线是 ROS1/Noetic 工程 | ROS1 只承担硬件兼容；项目自研统一放 ROS2 Humble，通过 bridge 连接，不迁移厂商核心 |
| UWB 原始测距接口未开放 | 用官方 `/odom_global_001`/飞控 SD 日志做 UWB 基线；删除无法验证的 Chan/Taylor/TDOA 对比 |
| 树莓派5算力不足以跑多相机 | 树莓派只跑 fcu_core/轻量回传，视觉和分析放外部主机；必要时使用幻思 Jetson 视觉套件 |
| 视觉输入接口未开放 | 先用官方 UWB + 光流完成演示；把机载 800 万像素相机标为待验证，ROS2 视觉节点不假设能直接读取 |
| ROS1/ROS2 bridge 时间或坐标映射错误 | 先离线回放验证 topic、单位、frame 和时间戳，再接入 `motion_001`；错误时退回 ROS1 官方 UWB 基线 |
| UWB硬件到货/调试延迟 | 第1周立即验收硬件，预留2天缓冲；先用仿真数据跑通算法逻辑，硬件到位后快速接入 |
| 视觉标定误差大 | 采用多次标定取平均、增加标定点数量；准备双目/多相机备用方案 |
| UWB与相机时间不同步 | 优先采用硬件同步（PTP/NTP），软件方案用插值对齐作为后备 |
| 现有三脚架无法架设新相机（如已被展厅监控占用） | 第1周第一时间和学校/实验室管理方确认这些三脚架及顶部设备的使用权限，若不可用则准备独立三脚架/支架方案作为备选 |
| 现场演示硬件故障 | 提前录制完整Demo视频作为Plan B，答辩现场优先实物演示+视频兜底 |
| 核心演示区精度未达5cm目标 | 第3周末做中期精度检查点；若未达标，优先检查相机标定质量和多相机基线布局（这两项对5cm级精度影响最大），必要时收窄核心演示区域范围、增加该区域相机密度，仍能保证30cm的硬指标兜底 |

## 十二、总结

这套方案的核心竞争力在于"复用幻思 FanciSwarm 官方 UWB/飞控/ROS 链路，以 UWB 飞控基线保证可飞，再用可接入的视觉链路做高精度修正"。外部多相机是 5cm 冲刺路线，不是未经接口验证的前置承诺；所有精度结论以官方 `fcu_core` 录包、视觉回传实验和实测报告为准。四周内先完成稳定飞行、数据闭环和可解释的对比结果，再决定是否增加更复杂的多相机权重或自定义滤波。
