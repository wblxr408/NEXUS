# 无人机高精度目标定位方法 —— 项目实施规划书

**项目类型**：UWB + 视觉融合定位系统（ROS2）
**团队规模**：5人
**周期**：4周
**精度目标**：核心演示区 ≤ 5cm（视觉可见时），全场景兜底 < 30cm（依据学校提供沙盘的实测特征，5cm 是有充分技术依据的冲刺目标，详见第二节）
**开发模式**：全程 AI-Agent（Claude Code）辅助开发

---

## 一、总体技术路线

单一传感器都有各自的天花板，所以整个方案的核心思路不是"选一个最好的算法"，而是**做一套 UWB + 视觉的互补融合定位系统**，让两种技术互相弥补短板：

| 传感器 | 优势 | 短板 |
|---|---|---|
| UWB（超宽带） | 全空间覆盖、不受光照/遮挡影响、成本低、易部署 | 静态精度一般在 10～30cm，易受多径/NLOS（非视距）干扰 |
| 视觉（AprilTag/ArUco + 相机） | 视线内精度可达毫米～厘米级，姿态信息丰富 | 依赖光照与视线，易被遮挡，视场角有限 |

**技术路线**：UWB 提供全局、鲁棒的粗定位（兜底，防止视觉丢失时"断线"）+ 视觉在可视范围内提供高精度修正（挑大梁，真正把精度做出来）→ 通过时间同步与坐标统一后，用**融合算法（推荐 EKF/UKF 起步，有余力上因子图优化）**输出最终目标坐标。

需要明确一个关键认知：**UWB 单独定位的物理精度天花板一般在 10～30cm**（受限于测距误差和多径效应，即使换算法也很难稳定突破个位数厘米），**真正能把精度做到 5cm 级的是视觉**，尤其是在你们这种小尺度室内沙盘场景下（详见第二节的实测分析）。所以融合策略上要清楚分工：**视觉可见时以视觉为主导（目标 ≤5cm），UWB 只做粗定位背景和视觉丢失时的降级兜底（此时精度回落到 15～25cm，属于正常合理区间）**，不要指望靠"融合算法"把 UWB 的物理精度上限提上去——那是融合算法做不到的事，答辩时如果被问到这点，坦率讲清楚"精度的主力来源是谁"反而显得更专业。

## 二、场地实测特征与 5cm 精度冲刺方案

根据学校提供的沙盘实拍照片，这是一个**室内桌面级"十字路口+城市建筑群"沙盘**（有车道、斑马线、红绿灯、树木、储罐建筑模型），周边已经架设了多组三脚架式摄像头/补光灯装置，整体尺度在 3 米量级、层高不高（有吊顶灯槽和大屏幕，头顶空间有限）。这几个客观条件其实都在帮你们，把精度目标从"保底 30cm"上调到"冲刺 5cm"是有扎实技术依据的，不是喊口号：

### 1. 为什么这个场地能支撑 5cm 精度

| 场地特征 | 对精度的影响 |
|---|---|
| 沙盘尺度小（3米量级） | UWB 基站基线短、覆盖冗余度高，多径/NLOS 问题比开阔场地轻得多；相机离目标近，画面里目标占的像素数多，视觉解算精度天然更高 |
| 四周已有多组三脚架摄像头 | 现成的**外部多相机围观阵列**基础设施，比只靠无人机机载单相机的方案精度高一个量级（原理接近简化版动作捕捉系统） |
| 场景内建筑、路口、红绿灯等固定地标丰富 | 天然的高精度标定参考点，不需要额外画网格，标定误差来源更少 |
| 室内环境，光照可控、无风扰 | 排除了室外风扰、强光过曝等干扰视觉解算精度的因素 |

### 2. 落地 5cm 的具体技术手段（按优先级）

**① 视觉系统从"单机载相机"升级为"外部多相机阵列主导"**
这是把精度从 10~20cm 拉到 5cm 内的**最关键改动**。具体做法：
- 复用沙盘四周已有的三脚架位置，加装 3～4 台**全局快门（global shutter，不要用卷帘快门/rolling shutter）工业相机或高清USB相机**，围绕沙盘布置，尽量做到相互之间基线角度大（>30°），减少三角测量的几何误差
- 相机分辨率建议 1080P 起步，条件允许上 4K —— 场地小，相机离目标近，分辨率越高，每厘米覆盖的像素数越多，亚像素级角点检测的精度红利越明显
- 用多相机同步 AprilTag/ArUco 检测 + 三角测量（而不是单相机 PnP），多视角互相校验能显著抑制单相机因视角/畸变带来的系统性偏差
- 相机外参标定务必做**多角度、多位置的棋盘格标定**（不少于20组不同角度的标定图像），这是视觉精度的地基，标定草率做，后面算法再好也补不回来

**② UWB 基站部署做几何优化（GDOP优化）**
- 4 个基站尽量部署在沙盘四角、且抬高到略高于目标飞行高度（可直接绑在现有三脚架顶部），基站间基线拉满、几何分布均匀，能有效降低定位的几何精度稀释（GDOP），把 UWB 静态精度往 10cm 以内的区间靠拢
- 如硬件条件允许（预算内），可以问学校是否有更高精度型号的 UWB 模块（如支持 TDOA 且标称精度 ±5~10cm 的型号），但即使普通型号，在这么小的场地里通过基站布局优化也能明显提升

**③ 硬件级时间同步**
- 视觉和 UWB 数据的时间戳如果没对齐，运动状态下几厘米的误差会凭空出现。优先用 PTP（精确时间协议）或至少用统一的硬件触发信号同步相机曝光和 UWB 采样，不要只依赖 ROS2 消息到达时间做软件插值对齐

**④ 无人机本体选型要匹配场地**
- 沙盘尺度小、层高有限，**必须选室内小型/微型无人机**（如 Tello EDU、Crazyflie 级别，带桨叶保护罩），不能用室外大轴距机型——这不只是安全问题，机身越小、飞行越稳，对定位精度的动态测试也越有利（大机身的姿态抖动本身就会引入定位噪声）
- 目标物（AprilTag/ArUco标签）贴在无人机顶部或底部，标签尺寸要根据相机到目标距离反算，太小会降低检测稳定性，太大会增加机身负重和风阻

**⑤ 演示验证点结合沙盘已有地标设计**
- 沙盘上的路口中心、建筑物顶角、红绿灯杆基座这些位置本身就是可以精确量出物理坐标的天然标定点/验证点，比额外贴标记点更省事也更有说服力——演示脚本可以设计成"无人机依次悬停在3-4个指定路口/建筑上方，现场读出与真实坐标的偏差"，故事性和可信度都比空场地里飞更强

**⑥ 精度分级要向答辩评委讲清楚**
建议在报告和PPT里明确区分三档精度，不要笼统只说一个数字：
- **视觉可见 + 融合稳定区**：目标 ≤5cm（核心演示区域，重点展示）
- **视觉部分遮挡 + 融合过渡区**：8~15cm
- **纯UWB降级兜底区**：15~25cm（低于30cm的任务硬指标）

这种分级恰恰是"技术严谨"的体现——比一个笼统的"全场5cm"更让人信服，也更贴近工程真实情况。

## 三、四项任务的具体落地方案

### 任务1：ROS2 环境搭建

- **版本选择**：ROS2 Humble（LTS，稳定，生态成熟，Ubuntu 22.04）或 Jazzy（若硬件驱动/SDK 支持更好则选 Jazzy）。建议直接用 Humble，兼容性风险最低。
- 搭建内容：
  - 基础环境 + colcon 工作空间 + 各功能包骨架（uwb_driver, vision_localization, fusion_node, viz_dashboard, coord_transform）
  - 统一使用 ROS2 的 `tf2` 管理坐标系树，`message_filters` 做多传感器时间同步
  - 用 Docker 容器化整套环境，保证 5 人开发环境一致、可快速在实物硬件上复现，避免"在我电脑上能跑"的问题
  - 用 `rosbag2` 记录所有实验数据，便于算法迭代和答辩时的数据复盘

### 任务2：现有定位算法精度比较，选定厘米级方案

这是决定项目上限的关键任务，建议做**系统性对比实验**而不是直接选定一个算法，这本身也是答辩的加分项（体现严谨性）。

**UWB 定位算法候选**：
- 最小二乘法（LS）三边定位 —— 基线方案，实现简单
- Chan 算法（TDOA 闭式解）—— 计算快，适合实时
- Taylor 级数迭代法 —— 精度更高但依赖初值
- 基于残差加权的鲁棒最小二乘（抗 NLOS 异常值）

**视觉定位算法候选**：
- 单目 + AprilTag/ArUco + PnP 解算 —— 部署简单，需已知标签尺寸
- 双目立体视觉 + 三角测量 —— 不依赖已知标签尺寸，精度更稳
- 多固定相机（复用沙盘四周三脚架）+ 多视角三角测量 —— 类动捕方案，精度最高，是本项目视觉精度的主力方案。**落地工具建议直接用开源库 `mprib/caliscope`（多相机标定+三角测量，专为动捕工作流设计），不需要自己从零推导多相机标定算法**，只需要在它输出的3D坐标基础上接一层 ROS2 节点对接融合模块（这部分开源工具选型详见团队另附的《开源模块选型图》）

**评估维度**（做成对比表格，是答辩的核心图表之一）：
精度（RMSE/CEP95）、更新频率、抗遮挡能力、算力消耗、部署成本、环境适应性

**建议结论方向**：UWB 用"鲁棒加权最小二乘 + NLOS 检测剔除"做全局兜底，视觉用"多相机（复用沙盘现有三脚架）AprilTag 三角测量"做精度主力。结合你们沙盘的小尺度室内条件，视觉主导区间做到 5cm 级是有依据的目标（详见第二节的场地分析），UWB 兜底区间维持在 15~25cm，全场景不低于 30cm 硬指标。

### 任务3：坐标转换

- 建立三级坐标系：**传感器坐标系 → 无人机机体坐标系 → 沙盘世界坐标系**
- 标定流程：
  1. UWB 基站坐标高精度测量（用卷尺+已知参考点，或如学校有全站仪则更佳）作为世界坐标系锚点，**基站的具体摆放位置需先跑一版自己写的 GDOP（几何精度稀释度）优化脚本，在沙盘四角范围内搜索几何分布最优的4个点位，而不是随手摆**
  2. 相机内参+外参标定：多相机阵列直接用 `caliscope` 自动完成——它专门解决"每台相机内参+相互之间外参"的联合标定问题，不需要自己手写张正友标定法的多相机版本，标定board多角度多位置拍摄即可出结果
  3. UWB 坐标系与视觉坐标系之间用最小二乘拟合刚体变换（ICP 或 SVD 求解旋转平移矩阵）统一到同一世界坐标系
- 全部变换关系注册进 ROS2 的 `tf2` 树，融合节点直接订阅 `tf2` 输出的统一坐标，避免手写坐标转换代码导致的隐蔽 bug

### 任务4：演示应用

- **实时可视化**：RViz2 展示无人机实时位置、UWB原始估计、视觉估计、融合后轨迹（不同颜色区分），直观展示"融合比单一传感器更准"
- **Web Dashboard**（加分项）：用一个轻量 Web 页面实时展示定位坐标、误差曲线、精度统计（RMSE/CEP95），适合答辩现场演示，比纯 RViz 更有视觉冲击力
- **精度验证演示**：在沙盘上设置若干已知坐标的标定点，让目标物/无人机依次停靠，现场读出定位误差，用数据说话
- **动态轨迹演示**：无人机按预设路径飞行，实时展示跟踪轨迹与误差热力图

## 六、AI-Agent（Claude Code）全程协助策略

明确各环节让 AI-Agent 发挥最大价值，而不是仅当"代码补全工具"：

1. **脚手架生成**：ROS2 package、launch文件、msg/srv定义 —— 一键生成规范代码框架，节省重复劳动
2. **算法原型验证**：UWB多种解算算法、EKF/UKF公式推导与代码实现，AI快速生成多版本对比代码
3. **自动调参**：融合算法的过程噪声/观测噪声协方差矩阵，用AI辅助设计贝叶斯优化/网格搜索脚本自动寻优，比人工试参数快得多
4. **调试排障**：坐标变换错位、时间戳不同步等典型 bug，让 AI 分析日志/tf树输出定位问题
5. **文档与答辩材料**：技术报告初稿、PPT大纲、算法对比表格自动生成，团队再做精修
6. **代码审查**：每个模块合并前用 AI 做一轮代码review，统一代码风格、发现潜在bug
7. **数据分析**：rosbag录制数据的自动化精度统计脚本（RMSE/CEP95计算、误差可视化）

> 建议为团队制定一份《AI-Agent使用规范》，明确哪些环节必须人工复核（如坐标标定的物理测量数据、最终精度结论），避免完全依赖AI导致答辩时说不清楚原理。

## 七、精度指标与验证方案

- **核心指标**：
  - RMSE（均方根误差）
  - CEP50 / CEP95（50%/95%置信区间圆概率误差）
  - 最大误差（Max Error）
  - 更新频率（Hz）与延迟
- **验证方法**：
  - 静态测试：在沙盘的路口中心、建筑角点等天然地标上标定 8～10 个已知精确坐标的测试点，逐点采集定位数据统计误差
  - 动态测试：无人机沿预设轨迹（直线、圆形、"8"字"，尽量沿着沙盘车道走）飞行，与规划轨迹做误差对比
  - 遮挡/异常场景测试：人为遮挡视觉标签、制造UWB多径干扰，验证降级机制是否稳定接管
  - 对比实验：分别记录"仅UWB""仅视觉（单相机PnP）""仅视觉（多相机三角测量）""融合后"四组数据，用图表直观证明"多相机方案比单相机方案精度提升多少""融合比单一传感器更稳"（这是答辩的核心说服力图表，也直接对应任务2要求的算法精度比较）
  - **分级精度报告**：按第二节提出的三档（视觉主导区 ≤5cm / 过渡区 8~15cm / UWB兜底区 15~25cm）分别统计并可视化成误差热力图，比单一均值更有说服力

## 八、创新点建议（提升技术优秀度）

1. **自适应融合权重**：融合算法中不用固定协方差矩阵，而是根据UWB测距残差、视觉重投影误差实时估计各传感器置信度，动态调整融合权重
2. **NLOS/遮挡智能降级机制**：设计状态机，当视觉丢失目标时无缝切换到纯UWB模式，UWB出现多径异常时用视觉数据做修正，保证系统连续性而非"掉线"
3. **图优化后端（进阶）**：如有余力，用因子图优化（GTSAM）替代纯滤波方案，能更好处理非线性、非高斯误差，是比EKF更前沿的方案，答辩时是明显加分项
4. **误差可视化Dashboard**：实时误差热力图，直观展示沙盘不同区域的定位精度分布，体现工程严谨性
5. **多机协同定位（如有多台无人机/多目标）**：UWB网络协同定位，提升整体覆盖精度
6. **多相机外部阵列的置信度加权融合**：`caliscope` 本身只输出多相机三角测量后的3D坐标，不做置信度加权；在其基础上二次开发——根据每台相机与目标的距离、视角、检测置信度动态加权，距离更近、角度更正的相机权重更高，这是把视觉精度从10cm量级压到5cm量级的关键工程细节，也是很有讲头的创新点

## 九、风险与应对预案

| 风险 | 应对措施 |
|---|---|
| UWB硬件到货/调试延迟 | 第1周立即验收硬件，预留2天缓冲；先用仿真数据跑通算法逻辑，硬件到位后快速接入 |
| 视觉标定误差大 | 采用多次标定取平均、增加标定点数量；准备双目/多相机备用方案 |
| UWB与相机时间不同步 | 优先采用硬件同步（PTP/NTP），软件方案用插值对齐作为后备 |
| 现有三脚架无法架设新相机（如已被展厅监控占用） | 第1周第一时间和学校/实验室管理方确认这些三脚架及顶部设备的使用权限，若不可用则准备独立三脚架/支架方案作为备选 |
| 现场演示硬件故障 | 提前录制完整Demo视频作为Plan B，答辩现场优先实物演示+视频兜底 |
| 核心演示区精度未达5cm目标 | 第3周末做中期精度检查点；若未达标，优先检查相机标定质量和多相机基线布局（这两项对5cm级精度影响最大），必要时收窄核心演示区域范围、增加该区域相机密度，仍能保证30cm的硬指标兜底 |

## 十二、总结

这套方案的核心竞争力在于"复用沙盘现有多相机基础设施（借助开源库 `caliscope` 做标定与三角测量）做外部视觉阵列主导定位 + UWB兜底降级 + 自适应权重融合"，精度目标从保底30cm上调到核心区5cm，是基于场地实测特征（小尺度室内、已有相机支架、丰富固定地标）给出的有技术依据的冲刺目标，而不是空喊口号。整个方案不是简单调用某个现成算法库，而是有明确的算法对比、工程化的坐标标定流程、分级精度验证体系，四周周期内可以扎实落地并做出有说服力的答辩成果。
