# 算法复现所需硬件信息与接口验收清单

- 日期：2026-08-24
- 类型：checklist
- 状态：pre_hardware_ready
- 关联：`ADR-005`、`ADR-006`、`ADR-007`、`2026-08-24_research_reusable_localization_algorithms.md`
- 用途：在无人机、沙盘与地面电脑首次联调时，确认哪些已有算法能真实复现；不以规格图、厂商标称或代码可编译代替接口验收和精度结果。

## 项目范围约束（本阶段不做扩展）

本项目当前只验证以下主链路：**UWB 提供无人机自身在 `map` 中的平台位姿，机载单目相机通过 AprilTag + PnP/IPPE 定位无人机之外的目标，再完成坐标变换与结果迭代**。因此，下面的字段按主链路划分；VINS、ORB-SLAM3 惯性模式、UVINS、光流融合和 GNSS 融合仅作为资料中的后续候选，不是本阶段交付内容，也不应为它们额外采购或改造硬件。

### 主链路必须确认

1. **图像输入**：地面端能持续取得图像；实际宽高、像素格式和有效帧率明确。
2. **图像时间**：每帧至少保留可用于和 UWB 位姿配对的采样/采集时间；接收时间可另存，但不能覆盖原始时间。
3. **相机标定**：与实际输出分辨率对应的内参 `K`、畸变模型/参数 `D`。
4. **相机外参**：`base_link → camera_optical_frame` 的平移、旋转和轴向定义。
5. **目标几何**：AprilTag 编号、实际边长，以及标签参考点到 `target_link` 的关系。
6. **平台位姿**：无人机自身位置和将相机观测变换到 `map` 所需的姿态。坐标原点、轴向和内部单位由项目统一定义；只需确认厂商输出字段能否映射到该定义，不能映射的部分由项目适配或测量补齐。
7. **UWB 标签外参**：UWB 标签参考点相对无人机 `base_link` 的安装关系；若厂商输出已经定义为机体参考点，必须取得其明确说明。

### 可用于主链路但不作为首版阻塞项

- 图像帧序号：用于发现丢帧和回放，算法数学输入不是必需。
- UWB 质量/协方差：用于异常值剔除和结果解释；没有时可先记录原始值并标记限制。
- 曝光、增益、快门类型：用于解释运动模糊和检测失败，不是首版 PnP 的接口硬门槛。
- 相机型号、视场角和镜头参数：有助于选取标签尺寸和拍摄距离，但不能替代实际标定。

### 本阶段明确不纳入

- 原始 IMU、相机–IMU 硬件同步、VINS-Mono/ORB-SLAM3 惯性模式；
- 四基站原始 TWR/TDOA、UVINS、Chan 或自研 UWB 原始测距解算；
- 光流融合；
- GNSS 融合；
- YOLO 或其他目标检测扩展（首版目标使用已知 AprilTag）。

因此，官网检索应优先围绕“相机图像输出与标定、UWB 实际输出字段、安装外参”进行；坐标原点、轴向约定、单位换算和 `map` 定义由项目记录，不需要再向老师确认。

## 飞控数据接口确认

以下内容来自官方 Mcontroller V7 页面、官方 `fcu_core` 工程及其 MAVLink 消息定义。它们是“接口存在/代码会解析”的事实，不代表已经完成实机频率、单位和语义验收。

| 数据 | 外部协议字段 | 已确认单位/含义 | 当前 ROS 输出 |
|---|---|---|---|
| 加速度 | `SCALED_IMU.xacc/yacc/zacc` | `mG` | `/imu_global_001` 的 `linear_acceleration` |
| 角速度 | `SCALED_IMU.xgyro/ygyro/zgyro` | `mrad/s` | `/imu_global_001` 的 `angular_velocity` |
| 磁场 | `SCALED_IMU.xmag/ymag/zmag` | `mgauss` |  |
| IMU设备时间 | `SCALED_IMU.time_boot_ms` | 飞控启动后的毫秒时间 | 当前 `fcu_core` 未写入 ROS header |
| 平台位置/姿态 | `GLOBAL_VISION_POSITION_ESTIMATE.x/y/z/roll/pitch/yaw` | MAVLink 定义为 `m`、`rad`；当前桥接代码对位置乘 `0.01` 并反转 z | `/odom_global_001` |
| GNSS/速度 | `GLOBAL_POSITION_INT.lat/lon/alt/vx/vy/vz/hdg` | `degE7`、`mm`、`cm/s`、`cdeg` | `/gnss_global_001`；速度被用于 `/odom_global_001` 的 twist |

当前 `fcu_core` 还会解析 `HEARTBEAT`、`BATTERY_STATUS`、`ATTITUDE_QUATERNION` 和 `SET_POSITION_TARGET_LOCAL_NED`；这些不是 VINS 首要输入。

当前桥接实现用 ROS 接收时刻填充 `header.stamp`，没有把 `SCALED_IMU.time_boot_ms` 写入 ROS 消息；加速度也只做了 `mG / 1000`，尚未转换为 `m/s²`。这两项是代码现状，不是已经完成的 VIO 接口验收。

### Mcontroller V7 官方开发页与固件源码对“平台位姿”字段的逐项核对

官方页面明确提供了[姿态/传感器数据接口说明](https://fancinnov.com/support-Mcontroller-v7)，并链接到
[`Mcontroller-v7-firmware`](https://github.com/fancinnov/Mcontroller-v7-firmware)。截至当前公开版本，能固定的内容如下；“源码存在”不等于当前飞控已经按该配置运行。

| 所需字段 | 官方页面/源码能固定的内容 | 结论与限制 |
|---|---|---|
| 无人机位置 `x/y/z` | `common.h` 提供 `get_uwb_x/y/z()`；`get_pos_x/y/z()` 注释单位为 `cm`；固件把 `get_pos_*()` 写入 `GLOBAL_VISION_POSITION_ESTIMATE.x/y/z` | **字段和源码单位注释已确认，但不是“纯 UWB 输出”的保证**。公开默认配置为 `USE_UWB=0`、`USE_GNSS=1`；即使启用 UWB，发送函数使用的是 `get_pos_*()`（可能为 EKF/融合位置），不是直接发送 `uwb_pos`。线上 MAVLink 单位还存在冲突，见下表说明 |
| 无人机姿态 | `ahrs_pitch_rad()`、`ahrs_roll_rad()`、`ahrs_yaw_rad()`；固件发送 `GLOBAL_VISION_POSITION_ESTIMATE.pitch/roll/yaw` | **欧拉角存在，单位为 rad**。公开发送代码未确认四元数输出；姿态是飞控估计值，不是 UWB 单独提供 |
| 坐标系 | 手册定义基站坐标系：X/Y 在地面平面、Y 轴位于 X 轴右侧、Z 轴向上；源码另有 NED/FRD 姿态约定 | **参考轴向已确认**。项目将手册基站坐标系作为 `map`，不再等待老师定义；只需联调验证 `uwb-x/uwb-y` 的符号和轴向 |
| 单位 | 手册配置坐标单位为 `cm`；源码位置内部注释为 `cm`，姿态为 `rad`；MAVLink 标准字段可能按 `m` 解释 | **项目内部统一使用 m/rad**；适配层根据实际 UWB/MAVLink 报文确认并转换输入单位，不把单位问题升级为老师确认项 |
| 坐标原点 | 手册给出基站坐标系原点 O，现场可按条件调整基站坐标 | **由项目定义**：选定沙盘地面基准点为 `map` 原点，并将实际基站坐标写入配置；不是厂商未提供而无法确定 |
| 时间戳 | `GLOBAL_VISION_POSITION_ESTIMATE.usec = HAL_GetTick()`；`GLOBAL_POSITION_INT.time_boot_ms = time - takeoff_time`（未起飞时为 0） | **有协议时间字段，但不是明确的 UWB 采样时间**。`HAL_GetTick()` 的毫秒语义与字段名 `usec` 不一致；图像/UWB采样时刻关系仍未知 |
| 更新频率 | UWB 位置更新调用位于 `Loop50hzTask`；MAVLink 分发位于独立 `MavSendTask` | **只能确认存在 50 Hz 位置更新任务**；不能据此固定 UWB 输出或 MAVLink 位姿消息实际频率，需抓包统计 |
| 输出质量/协方差 | 固件内部 EKF 有方差参数，但 `GLOBAL_VISION_POSITION_ESTIMATE` 发送结构未包含质量/协方差字段 | **未确认有可用的位姿质量或协方差输出** |
| 纯 UWB 位姿外部接口 | 手册明确显示 `uwb-x/uwb-y` 与全局 `x/y` 两组数据；固件内部有 `uwb_pos` 和 `get_uwb_x/y/z()` | **项目优先选用 `uwb-x/uwb-y` 作为平面 UWB 输入**；具体 ROS/MAVLink 字段映射和是否有融合层由首次抓包确认，不需要向老师定义 |
| UWB 标签相对 `base_link` 外参 | 公开页面和固件源码未给出标签安装点、机体参考点或 CAD 外参 | **未确认，必须现场测量/标定或向厂商索取** |

固件当前公开配置还包含 `UWB_TAG_ID=1`、`UWB_TAG_MAX=1`，以及四个示例基站坐标（单位按源码用法为 cm）：
`(80,-80,160)`、`(0,400,170)`、`(400,400,170)`、`(400,0,170)`。这些只能登记为“固件默认参数”，不能当作你们实际四基站坐标；现场坐标、编号对应关系和布局版本仍需确认。

**对当前主链路的结论：** 官方资料确认了“可以取得 UWB 平面坐标、四基站距离和飞控姿态/飞行状态字段”。项目自行定义 `map` 原点、Z 轴和内部单位；启动 AprilTag + PnP/IPPE 前只需完成实际报文映射、时间配对验证和外参测量，不需要再向老师确认坐标原点或单位选取。

项目组已确认实际使用的固件启用了 UWB；因此“是否使用 UWB”不再是项目未决项。公开固件仓库中的默认配置仍可能显示 `USE_UWB=0`，只代表源码默认值与实际部署配置不同；运行记录中登记实际 App/固件参数即可。`uwb-x/uwb-y` 与全局 `x/y` 的具体消息映射由实际报文确认。

### UWB 官方手册新增确认内容

来源：项目组提供的 FanciSwarm® UWB 基站摆放和定位参数手册页面。以下是手册明确写出的事实：

| 项目 | 手册确认值 | 仍需注意 |
|---|---|---|
| 基站数量与角色 | 4 个基站，固定布置在基站坐标系中；无人机携带 UWB 标签 | 机外目标当前不配置第二个 UWB 标签 |
| 参考基站坐标（cm） | 基站1 `(80,-80,160)`；基站2 `(0,400,170)`；基站3 `(400,400,170)`；基站4 `(400,0,170)` | 这是参考配置；可按场地调整，现场最终坐标必须重新测量和登记 |
| 基站编号 | `1`～`4`，配置参数必须按 ID 对应 | 现场编号不能与坐标表错配 |
| 基站坐标系 | X、Y 位于地面平面；Y 轴在 X 轴右侧；Z 轴垂直地面向上 | 项目采用该基站坐标系作为 `map`；用静止已知点验证 UWB 输出符号即可 |
| 基站姿态 | UWB 模块竖直向下、向前仰 `10°`，并朝向坐标系内侧 | 这是安装要求，不是无人机姿态输出字段 |
| 基站高度/安全间距 | 基站高度高于无人机飞行高度；飞行轨迹距任一基站大于 2 m；距墙壁、天花板或金属物体至少 15 cm | 属于布置准入条件，现场需测量记录 |
| 无人机定位参数 | 坐标偏航角、标签 ID、标签总数、基站1～4坐标 | 参数通过 FanciSwarm App 设置，修改后需重启无人机 |
| 标签 ID | 整数，从 1 开始；不同无人机使用不同 ID | 标签 ID 与 ROS 节点对应，例如 ID 1 对应 `fcu_bridge_001.cpp` |
| 标签总数 | 整数，等于当前开机并参与 UWB 定位的无人机数量 | 多机实验时必须与实际在线数量一致 |
| 坐标偏航角 | 整数；无人机机头与基站坐标系 X 轴正方向平行时，在 App 姿态球读取该偏航角 | 这是坐标对齐/配置参数，不等于每条位姿消息的 yaw 时间序列 |
| 飞行数据 | 起飞时间、对地高度、水平速度、垂直速度、主模式、子模式 | 手册确认字段存在，但协议名称、单位、时间戳和频率仍需接口/日志确认 |
| UWB 定位数据 | 定位状态、全局坐标 `x/y`、`uwb-x`、`uwb-y`、到基站1～4的距离 | 二维 UWB 输入已确认；项目定义 `z=0` 为沙盘地面，平台 Z 优先取对地高度；单位在适配层统一为 m，原始字段单位和消息映射首次抓包确认 |

手册因此确认了“实际 UWB 平台数据包含二维位置和四基站距离”。三维链路中的 `z=0` 地面基准、坐标原点和内部单位由项目定义；平台 Z 使用手册提供的对地高度字段，姿态和各字段的具体 MAVLink/ROS 映射在首次抓包时确认。

### `fcu_core_v2` 的 `uwb_distance` 语义（源码确认）

官方页面配套的 `fcu_core_v2` 在 launch 中将 `~uwb_distance` remap 到
`uwb_distance`，并由 `fcu_bridge_001.cpp` 发布
`std_msgs/Float32MultiArray`。源码当前确认的字段语义如下：

| 字段 | 类型/单位 | 语义 |
|---|---|---|
| `data[0]` | `float`，秒 | ROS 接收端当前时间（不是飞控硬件时间戳） |
| `data[index]` | `float`，m | 通过 `MAV_CMD_CONDITION_DISTANCE` 解析出的机间距离；本机对应项为 0 |
| 数组长度 | 最多 6 个机位 | 由消息中的目标系统编号映射 |

该话题表示的是**机间距离**，不是四基站到无人机的原始 UWB 测距，也不是
TWR/TDOA 原始观测；因此不能直接作为 UVINS、Chan 或最小二乘 UWB 解算的输入。
如需复现这些算法，仍需向厂商确认并导出每个基站的原始距离、基站编号、测量时间戳
和单位。`data[0]` 只能用于记录接收时刻，不能替代传感器采样时间。

“树莓派没有 ROS、系统不是 Ubuntu”只说明**机载端不能被默认当作 ROS 节点运行**；它不等于不能复现视觉算法。可让树莓派或厂商程序只采集并传输图像/时间戳，地面 Ubuntu 电脑的 ROS2 节点再转换为 `Image`、`CameraInfo` 并运行算法。能否这样做取决于下文的图像导出与网络信息。

## 二、算法与最小硬件输入对应表

| 候选算法/论文简称 | 能复现什么 | 必须有的实时/录包输入 | 必须有的静态标定信息 | 当前判定 |
|---|---|---|---|---|
| AprilTag 2 + IPPE（`apriltag_ros` + PnP） | 机外目标相对相机的 6DoF 位姿；结合平台位姿后得到 `map → target_link` | 每帧图像、图像采样时间、连续帧序号 | `CameraInfo`、镜头畸变模型、AprilTag 实际边长、`base_link → camera`、`tag_target → target_link` | **首版可行，但相机输出未验收** |
| TagSLAM | 多 AprilTag 的相机/标签因子图优化、静态布局或重复观测对照 | 同上；每帧检测/图像时间戳 | 同上；各固定标签的已知或待估姿态定义 | **条件可行**；需另验 ROS 版本和动态目标行为 |
| VINS-Mono / VINS-Fusion 单目+IMU | 无人机自身 `base_link` 的单目视觉惯性位姿 | 单目图像 + 原始陀螺仪/加速度计；两路都必须有采样时间 | 相机内参/畸变、相机–IMU 外参、IMU 噪声参数、相机/IMU 时间偏移 | **未知**；没有这组同步输入就不尝试复现 |
| ORB-SLAM3 单目 | 单目相对轨迹，仅作视觉自身位姿对照 | 单目图像 + 图像时间戳 | 相机内参/畸变；场景需有足够纹理 | **条件可行**；没有绝对尺度，不能直接作为厘米级 `map` 结果 |
| ORB-SLAM3 单目+IMU | 尺度可观的视觉惯性轨迹对照 | 图像 + 原始 IMU + 同步时间戳 | 与 VINS 相同 | **未知**；条件同 VINS |
| UVINS / UWB-VIO | 多基站原始距离与 VIO 紧耦合，抑制自身位姿漂移 | 图像 + 原始 IMU + 每个基站的原始 range/TDOA + 全部采样时间 | 相机–IMU、tag–IMU 外参、4 个基站坐标、噪声/时间模型 | **当前不适用**；先确认是否开放原始 UWB 距离 |
| 厂商 UWB + AprilTag/IPPE 坐标链 | 当前项目首版：UWB 给 `map → base_link`，单目视觉给 `camera → target_link` | 厂商 UWB 位姿及时间戳 + 图像及时间戳 | UWB→`map`、`base_link → camera`、相机内参、标签尺寸/外参 | **主线候选**；需完成相机与 UWB 语义验收 |

注意：单目相机并不排除 VINS-Mono、VINS-Fusion 单目+IMU、ORB-SLAM3 单目模式；排除的是**强制要求双目左右图像或深度图**的配置。VIO 所需的关键不是深度相机，而是可用 IMU 与可靠的图像–IMU 时间关系。

## 三、机载相机必须取得的字段

### 3.1 每帧必须随图像保存或传输的字段

下表是地面端适配成 ROS2 `sensor_msgs/msg/Image` 时的最低契约。即使树莓派没有 ROS，也必须以厂商 SDK、文件名、CSV sidecar 或自定义 UDP/TCP 包保留等价字段。

| 字段 | 示例 | AprilTag/IPPE | TagSLAM | VINS / ORB-SLAM3 | 为什么需要 |
|---|---|---:|---:|---:|---|
| `frame_sequence` | `1842` | 必须 | 必须 | 必须 | 判断丢帧、乱序、重复帧 |
| `sample_timestamp_ns` | `1724476800123456789` | 必须 | 必须 | 必须 | 图像**曝光/采样时刻**，不是到地面电脑的接收时刻 |
| `timestamp_clock` | `rpi_monotonic_raw` | 必须 | 必须 | 必须 | 说明时间戳属于树莓派、飞控还是地面电脑；没有时钟来源无法对齐 |
| `image_width_px` / `image_height_px` | `3280` / `2464` | 必须 | 必须 | 必须 | “800 万像素”不是实际输出模式；算法需要真实尺寸 |
| `encoding` / `pixel_format` | `mono8`、`bgr8`、`yuyv`、`mjpeg`、`h264` | 必须 | 必须 | 必须 | 正确解码、评估压缩延迟；应记录原始格式与转换格式 |
| 图像字节或外部文件位置与 SHA256 | `frames/frame_001842.jpg` | 必须 | 必须 | 必须 | 让同一数据可回放；大文件不提交 Git，只登记外部位置与校验值 |
| `exposure_start_timestamp_ns` 或曝光时长 | `8_000_000` ns | 建议 | 建议 | 建议 | 快速运动时，曝光中点与帧到达时刻不同；用于分析运动模糊/同步误差 |
| `gain`、`exposure_us`、自动曝光/白平衡状态 | `gain=4.0` | 建议 | 建议 | 建议 | 解释检测率和特征跟踪失败，不能把照明变化误判为算法差异 |
| `camera_frame_id` | `camera_optical_frame` | 必须 | 必须 | 必须 | 建立相机坐标和 `base_link → camera` 外参；仅有字符串时仍需验证轴向 |

**禁止替代：** 不要用视频文件创建时间、Wi‑Fi 接收时间、ROS 发布时刻替代 `sample_timestamp_ns`。这些时刻可以另存为 `receive_timestamp_ns`，用于测量传输延迟，但不能用于 VIO 同步或坐标变换配对。

### 3.2 `CameraInfo`/相机标定必须具备的字段

| 字段 | 说明 | 适用算法 |
|---|---|---|
| `distortion_model` | 例如 `plumb_bob`、`rational_polynomial`、`equidistant`；必须与标定工具/图像矫正一致 | 全部视觉算法 |
| `K[3×3]` | 焦距和主点内参矩阵；不得用分辨率猜测 | AprilTag/IPPE、TagSLAM、VINS、ORB-SLAM3 |
| `D[]` | 畸变系数；鱼眼镜头尤其不能省略 | 全部视觉算法 |
| 标定图像的真实分辨率与裁切/缩放记录 | `K` 只对同一分辨率/裁切模式有效 | 全部视觉算法 |
| `R`、`P` | ROS `CameraInfo` 的校正/投影矩阵；单目可记录单位/标准形式 | ROS 适配和矫正图像 |
| 标定日期、工具、棋盘/Charuco 尺寸、重投影误差、配置 SHA256 | 让内参可重现与可替换 | 全部视觉算法 |

镜头还应记录：全局/滚动快门、焦距/视场角、自动对焦是否锁定、镜头是否可拆、图像是否已电子防抖/裁切。它们不一定阻止算法运行，但直接影响精度解释和快速飞行时的误差。

## 四、IMU、飞控与时间同步必须取得的字段

### 4.1 VIO 所需的原始 IMU 样本

如只做 AprilTag/IPPE + 厂商 UWB 坐标链，以下 IMU 不作为首版阻塞项；如要复现 VINS、ORB-SLAM3 的惯性模式或 UVINS，则每一个样本都必须有：

| 字段 | 单位/要求 | 说明 |
|---|---|---|
| `imu_sample_timestamp_ns` | ns，说明时钟来源 | 采样时刻，不是 ROS 接收时刻；相邻样本应单调递增 |
| `angular_velocity_x/y/z` | rad/s | 原始或已明确标定后的陀螺仪；须说明是否已滤波/融合 |
| `linear_acceleration_x/y/z` | m/s² | 原始或已明确标定后的加速度计；须说明是否包含重力/去重力处理 |
| `imu_frame_id` 与轴向 | 明确右手系及各轴物理方向 | 不能从 `imu` 或 `scaled_imu` 名称猜测轴向 |
| IMU 频率、抖动、丢样率 | 实测统计 | VIO 要求高频、连续输入；记录均值、P95 间隔和最大间隔 |
| 时间基准与精度 | 飞控 tick / RPi monotonic / UTC 等 | 判断可否与相机时钟配对 |
| 噪声密度、随机游走、量程、滤波 | 厂商资料或静态实测 | VINS/ORB-SLAM3 配置参数；未知时不得假装为真实值 |
| `orientation`、协方差 | 有则记录来源 | 可供诊断；不能把飞控 EKF 姿态当作“原始 IMU”而不注明 |

### 4.2 必须回答的同步问题

1. 相机帧时间戳由谁产生：图像传感器、树莓派驱动、树莓派应用、飞控还是地面电脑？精度和单位是什么？
2. IMU 时间戳由谁产生：STM32、`fcu_core`、ROS1 主机还是 ROS2 主机？
3. 树莓派与飞控是否共享硬件触发、PPS、串口同步信号或同一时钟？如果没有，两者偏移和漂移怎样估计？
4. Wi‑Fi 传输是否只改变 `receive_timestamp_ns`，且保留机载原始 `sample_timestamp_ns`？
5. 在 60 秒静止采集中，图像、IMU、UWB 的时间戳是否单调、是否跳变，实际频率和帧/样本丢失率是多少？

**最低结论规则：** 没有图像采样时间和 IMU 采样时间，VINS/ORB-SLAM3 的惯性模式/UVINS均为 `blocked`，而不是“先用接收时间试试”。若只有图像且无 IMU，ORB-SLAM3 单目可做功能对照，但其轨迹没有绝对尺度。

## 五、UWB、平台位姿与外参必须取得的字段

| 项目 | 首版坐标链需要 | UVINS / 自研 UWB 解算额外需要 |
|---|---|---|
| 平台 UWB 位姿 | `position(x,y,z)`、姿态是否存在、`sample_timestamp_ns`、`frame_id`、单位、标签物理对象、更新率、质量/协方差来源 | 同左，可作为比较基线 |
| 四个基站 | 每个 `anchor_id`、天线参考点 `x,y,z`、单位、坐标系、测量/录入方法、布局版本 | 同左；还要与每条 range 中的 `anchor_id` 精确对应 |
| 原始测距 | 首版不需要 | 每条 `range_m` 或 TDOA、tag ID、anchor ID、采样时间、质量/NLOS/LOS 标志、通道/PRF 等可得配置 |
| 标签/传感器安装 | UWB 标签参考点相对 `base_link` 的平移/旋转（或明确厂商输出定义） | `tag → IMU` 外参；更换安装位置即重新测量 |
| 坐标变换 | `map → base_link`、`base_link → camera`、相机光学轴向 | 同左，并需要所有测距实体在同一可追溯坐标系 |

厂商已解算的 `/odom_global_001` 可以作为无人机自身位姿输入；只有确认其标签对象、单位、轴向和采样时间后，才可进入 `map → base_link`。它不是原始四基站距离，不能直接喂给 UVINS、LS、Chan 或 Taylor 解算器。

## 六、树莓派无 ROS 时的最小传输契约

树莓派端可使用厂商程序、C/C++、Python、GStreamer 或系统相机工具；实现语言不是验收重点。每一帧在离开机载端前必须具备下列等价记录，地面 ROS 适配器不可重写其采样时间：

```text
frame_sequence: 1842
sample_timestamp_ns: 1724476800123456789
timestamp_clock: rpi_monotonic_raw
width_px: 1920
height_px: 1080
pixel_format: mjpeg
camera_frame_id: camera_optical_frame
exposure_us: 8000
gain: 4.0
payload: <image bytes, or external image/video reference + SHA256>
```

地面端收到后补充而非覆盖：

```text
receive_timestamp_ns: <ground host receive time>
transport: wifi_udp | wifi_tcp | file_copy
packet_loss_or_decode_error: <count/status>
```

若只能得到 H.264/MP4 视频，也要从采集端保存每帧或每个编码访问单元对应的采样时间与帧序号；仅有视频播放时间轴不够支持 VIO 同步，也不够解释视觉延迟。首版 AprilTag 可以先离线解码验证检测，但实时定位与 VIO必须保留上述时间字段。

## 七、首次硬件验收的执行顺序与交付证据

1. **记录系统与连接。** 写明树莓派操作系统、相机驱动/SDK版本、相机接口、飞控固件、`fcu_core` 提交、网络模式；不记录序列号、Wi‑Fi 密码或其他凭据。

3. **地面 ROS 相机适配。** 发布 `Image`、`CameraInfo` 和原始 `sample_timestamp_ns`；记录一帧 `ros2 topic echo`、topic 类型、消息定义和 `camera_optical_frame` 轴向。无 `CameraInfo` 时只能标记 `blocked`，不得编造 K/D。

6. **标定。** 在一次预约时段内做相机内参、`base_link → camera`、UWB基站坐标和目标标签外参；每份配置写入来源运行编号和 SHA256。

## 九、结论边界

- 当前规格图确认的是硬件存在和大致能力，不能确认任何消息字段、同步误差、算法可运行性或精度。
- 相机没有 ROS 并不阻塞算法；缺少图像导出、内参或采样时间才会阻塞相应算法。
- 首版应优先取得“图像 + `CameraInfo` + 图像采样时间 + UWB平台位姿时间/坐标语义”，复现 AprilTag/IPPE 坐标链；IMU同步和原始 UWB 测距确认后再投入 VINS/UVINS。
- 所有验收数据与配置均应登记到新建的 `experiments/runs/YYYY-MM-DD_Exxx_*`，大体积视频/rosbag只记录外部位置与 SHA256，不提交到 Git。
