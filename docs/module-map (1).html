01

UWB 定位层

幻思已经把 UWB 测距、定位和通信集成到 FanciSwarm/Mcontroller；本项目首先验证官方位置输出和飞控日志，再根据接口是否开放决定是否做原始测距算法对比。

fancinnov/fcu_core 官方基线

幻思官方 ROS1 工程，当前公开版本基于 Ubuntu 20.04 + ROS Noetic + catkin，支持机载电脑/远程主机，通过 USB `/dev/ttyACM0` 或 TCP `192.168.4.1:333` 与 Mcontroller 通信，并发布飞控/UWB/IMU/位置状态；ROS2 算法通过 bridge 接入。

github.com/fancinnov/fcu_core
FanciSwarm UWB ×4 机载分布式定位

四基站 + 机载 DWM1000 标签构成幻思 UWB 系统，位置估计在无人机端实时完成，不需要外部计算机才能得到基础位置。先用 App、`fcu_core` 和 SD 日志验证位置、延迟与静态误差；不要把它误写成 TDOA 或 Nooploop 协议。

fancinnov.com/FanciSwarm
cliansang/uwb-tracking-ros 可直接迁移

如果厂商没有开放原始四基站测距，只保留这类第三方仓库作为算法参考，不接入生产链路。公开 `fcu_core` 才是本硬件的通信基线。

官方接口优先
cliansang/positioning-algorithms-for-uwb-matlab 需少量适配

条件性使用：只有拿到幻思原始测距数据时，才把该仓库作为离线 LS/鲁棒 LS 参考。若接口只给官方 XYZ 位置，则删除 Chan/Taylor/TDOA 对比，改做官方基线、布局和误差实验。

github.com/cliansang/positioning-algorithms-for-uwb-matlab
madfolio/Least-Squares-Trilateration 可直接迁移

用 scipy.optimize.least_squares 实现的最简三边定位，仅作为拿到原始测距后的离线 baseline；不绕过幻思飞控直接接管飞行。

github.com/madfolio/Least-Squares-Trilateration
02

视觉定位层

AprilTag / ArUco 的检测与位姿解算仍是视觉主线，但幻思硬件资料只确认了 800 万像素机载相机和可选 Jetson/Raspberry Pi 视觉套件，未确认你们当前相机是否开放原始帧。因此多相机阵列是条件性冲刺模块，不是当前必需依赖。

mprib/caliscope 需适配 · 关键模块

条件性使用：自动求解多相机内外参并把2D观测三角测量成3D坐标。只有确认沙盘相机能输出原始帧、时间戳和内参后才接入；输出接到 ROS2 `tf2`，再经 bridge 映射为 ROS1 `motion_001`，不是直接接管飞控。

github.com/mprib/caliscope
christianrauch/apriltag_ros 可直接迁移

AprilTag 检测节点优先作为 ROS2 适配候选，订阅矫正图像和相机内参后输出标签位姿。先用 OpenCV/Python 跑通单路，再决定是否包装成 ROS2 节点。

github.com/christianrauch/apriltag_ros
OpenCV ArUco ROS2适配

基于 OpenCV 的 ArUco 检测参考，适合先快速搭演示场景。ROS 发行版不绑定，直接以你们实际图像输入和脚本为准。

OpenCV ArUco 文档
OpenCV + RealSense（可选） 需适配

若采用幻思 Jetson 视觉套件并配置 RealSense D435，可利用 RGB-D 提升位姿估计；当前树莓派5方案先不假设已经具备深度相机。

融合算法 & 参考架构层

融合部分的核心建议：先把幻思飞控内置 UWB/光流/EKF 当作飞行基线，ROS 端通过 `motion_001` 做视觉位姿回传和误差评估；只有实测证明需要时才增加轻量自适应修正。

Mcontroller 内置 EKF + fcu_core 飞行主线基线

幻思飞控已经提供 UWB、光流、GNSS、测距和 EKF 相关能力；官方 `fcu_core` 负责 ROS 与飞控之间的状态/位置/指令通信。第一版不重复实现一套飞控级滤波器。

04

需要自己写的模块

这几块没有能直接拿来用的开源项目，因为都和你们具体的沙盘、硬件摆放、创新点强相关。这也是团队真正的工作量所在，也是答辩时能讲清楚"我们做了什么"的部分。

UWB基站GDOP布局优化 四个基站在沙盘四角的具体摆放位置要根据几何精度稀释度(GDOP)计算最优布局，这是针对你们沙盘具体尺寸的优化计算，没有现成工具，需要自己写一个基站位置优化脚本（可以用简单的网格搜索+GDOP公式）。
多相机置信度加权融合 caliscope 能把多路相机三角测量成3D坐标，但"哪台相机看得更清楚就多信它一点"这种基于距离/视角/检测置信度的动态加权逻辑，需要自己在其输出基础上二次开发，这是把精度从10cm级压到5cm级的关键工程细节。
坐标标定 + ROS2 tf2 统一变换 UWB/飞控坐标系、视觉坐标系、沙盘世界坐标系三者的标定和刚体变换求解，是针对你们具体沙盘的物理测量+标定脚本，开源项目不会覆盖这部分。
自适应融合权重 先实现视觉位姿质量评估和 `motion_001` 回传；只有基线实测不足时，才增加根据视觉重投影误差/UWB位置残差调整权重的轻量修正。
遮挡/NLOS 降级状态机 视觉丢失时保持幻思飞控 UWB/光流基线；视觉恢复时再回传修正。状态切换只写最小可演示逻辑，不重复实现飞控安全保护。
Web Dashboard 前端页面 rosbridge解决了"数据怎么传到浏览器"，但页面本身（实时坐标、误差曲线、热力图的UI设计）要自己用HTML/JS或React写；ROS1 原始记录可保留为硬件证据。
精度评估与统计脚本 RMSE、CEP50/95、延迟和误差热力图针对你们测试点位，需要自己写 ROS1 rosbag/ROS2 ros2 bag/SD 日志后处理脚本。
全系统集成 launch 文件 把 ROS1 `fcu_core`、bridge、ROS2视觉、坐标转换、回传、可视化串成两侧 launch 和参数配置，这是把"缝合"落到工程上的最后一步。
整理时间：2026-08 · 官方硬件/软件资料优先于第三方仓库。当前主线是 FanciSwarm 四基站 + Mcontroller V7 + ROS1 fcu_core（Noetic/catkin）+ ROS2 Humble 算法层；视觉和第三方标定库必须先用实际输入验证。
质量核实：公开 fcu_core 仓库为幻思官方 ROS 工程，包含 fcu_bridge_001、MAVLink、USB/TCP 和 quadrotor_msgs；本项目不再列 Nooploop 驱动为依赖。
