01

UWB 定位层

硬件驱动直接决定能不能拿到原始测距/坐标数据，算法对比库直接支撑任务2的"精度比较"环节，不需要自己重新推导公式。

nooploop-dev/nlink_parser 可直接迁移

Nooploop 官方 UWB 驱动（LinkTrack 系列），C++ 编写，无需额外依赖库，串口通信直接解析成 ROS 消息。若学校提供的是 Nooploop 硬件，这是最省心的起点。

github.com/nooploop-dev/nlink_parser
nooploop-dev/nlink_parser2 可直接迁移 · 厂商官方

Nooploop 官方原生 ROS2 包（不是社区移植版）。文档规范、topic设计清晰、支持LinkTrack全系列产品，构建流程标准。星数不高是因为这是小众设备商的专用驱动包，但厂商一手维护的可信度远高于个人开发者的移植版，建议优先用这个而不是第三方 ROS2 port。

github.com/nooploop-dev/nlink_parser2
cliansang/uwb-tracking-ros 可直接迁移

如果硬件是 Decawave/Qorvo DWM1001 而不是 Nooploop，这个驱动更合适，而且自带一层卡尔曼滤波做平滑，RViz 可视化脚本也是现成的。

github.com/cliansang/uwb-tracking-ros
cliansang/positioning-algorithms-for-uwb-matlab 需少量适配

这个最关键：作者用真实 UWB 硬件（不是仿真）实现并对比了三边定位、最小二乘、Taylor级数、EKF、UKF 五种算法，直接对应任务2的"算法精度比较"。MATLAB代码需要移植成 Python/C++ 节点，但算法逻辑不用自己重新推导。

github.com/cliansang/positioning-algorithms-for-uwb-matlab
madfolio/Least-Squares-Trilateration 可直接迁移

用 scipy.optimize.least_squares 实现的最简三边定位，几十行代码，适合当 baseline 或者理解原理的起点，包在自己的 ROS2 节点里就能用。

github.com/madfolio/Least-Squares-Trilateration
02

视觉定位层

AprilTag / ArUco 的检测与位姿解算（PnP）都是非常成熟的开源领域。结合沙盘实测，视觉方案升级为"多相机阵列"，所以这里多了一个专门做多相机标定+三角测量的模块——它是把精度从单相机的10~20cm拉到5cm级的关键拼图。

mprib/caliscope 需适配 · 关键模块

专为动作捕捉工作流设计的多相机标定库：自动求解每台相机的内参+相互之间的外参（位置关系），并把多路2D观测三角测量成精确3D坐标——链式立体估计，不要求所有相机同时看到目标。这正是"复用沙盘四周三脚架做多相机阵列"方案缺的那块拼图。是Python库，需要自己写一层把输出接入ROS2的tf2和融合节点。

github.com/mprib/caliscope
christianrauch/apriltag_ros 可直接迁移

ROS2 官方级 AprilTag 检测节点，订阅矫正后的图像+相机内参，直接发布标签位姿到 /tf，也支持组合节点(composable node)做零拷贝通信，性能更好。多相机方案里每台相机各起一个实例即可。

github.com/christianrauch/apriltag_ros
JMU-ROBOTICS-VIVA/ros2_aruco 可直接迁移

基于 OpenCV 的 ArUco 检测 wrapper，自带命令行工具一键生成标签图片，输出所有检测到的标签 id + 位姿数组，非常适合快速搭演示场景。

github.com/JMU-ROBOTICS-VIVA/ros2_aruco
AIRLab-POLIMI/ros2-aruco-pose-estimation 可直接迁移

同时支持 RGB 和深度图像（如用 RealSense D435），深度信息能显著提升位姿精度，且支持同时检测多个标签，各自独立发布位姿，适合多目标场景。

github.com/AIRLab-POLIMI/ros2-aruco-pose-estimation
03

融合算法 & 参考架构层

融合部分的核心建议：不要从零手写 EKF，用工业级现成包做基础融合，把精力放在"自适应权重"和"降级机制"这些现成包没有的创新点上。

cra-ros-pkg/robot_localization 可直接迁移 · 强烈推荐

ROS2 官方标准的多传感器非线性状态估计包（EKF/UKF 都有），任意数量传感器融合，只需要写 yaml 配置文件把 UWB 和视觉的 pose topic 接进去即可，不需要自己实现滤波器，是融合层的地基。

github.com/cra-ros-pkg/robot_localization
maduwanthasl/ros2-ekf-localization 参考学习

一个"从零手写"的教学级 EKF 实现（GPS+IMU 融合），代码简洁、有精度评估和可视化脚本。当你们要在 robot_localization 基础上做自适应权重这类定制逻辑时，看这个理解原理比看官方源码快。

github.com/maduwanthasl/ros2-ekf-localization
mfurkannargul/drone-...-uwb-camera 强参考 · 需要移植

一个与你们项目几乎同构的本科毕业设计：无人机 UWB + 视觉（QR码）EKF融合定位，ROS1 + OpenCV。架构思路可以直接照搬，但代码是 ROS1，需要重写成 ROS2 节点。

查看仓库 →
ASIG-X/SFUISE2 进阶参考 · 难度较高

UWB+IMU 连续时间样条融合框架的 ROS2 版本，比 EKF 更前沿（因子图/优化类方法）。如果团队有余力冲刺"创新点"，可以参考其时间同步和状态估计思路，但直接照搬难度较高，建议只作为思路参考。

github.com/ASIG-X/SFUISE2
RobotWebTools/rosbridge_suite 可直接迁移

官方维护、有正式 ros2 分支，一键起 WebSocket 服务把 ROS2 话题暴露给浏览器。你们的 Web Dashboard 前端页面要自己写，但"前端如何拿到实时定位数据"这层桥接直接用它，不用自己写通信协议。

github.com/RobotWebTools/rosbridge_suite
04

需要自己写的模块

这几块没有能直接拿来用的开源项目，因为都和你们具体的沙盘、硬件摆放、创新点强相关。这也是团队真正的工作量所在，也是答辩时能讲清楚"我们做了什么"的部分。

UWB基站GDOP布局优化 四个基站在沙盘四角的具体摆放位置要根据几何精度稀释度(GDOP)计算最优布局，这是针对你们沙盘具体尺寸的优化计算，没有现成工具，需要自己写一个基站位置优化脚本（可以用简单的网格搜索+GDOP公式）。
多相机置信度加权融合 caliscope 能把多路相机三角测量成3D坐标，但"哪台相机看得更清楚就多信它一点"这种基于距离/视角/检测置信度的动态加权逻辑，需要自己在其输出基础上二次开发，这是把精度从10cm级压到5cm级的关键工程细节。
坐标标定 + tf2 统一变换 UWB坐标系、多相机阵列坐标系、沙盘世界坐标系三者的标定和刚体变换求解，是针对你们具体沙盘（利用路口/建筑地标做标定点）的物理测量+标定脚本，开源项目不会覆盖这种场地特定的标定流程。
自适应融合权重 robot_localization 默认用固定协方差矩阵，你们要做"根据UWB测距残差/视觉重投影误差动态调整权重，且视觉可见时以视觉为主导"，需要在其基础上写自定义融合节点或替换协方差更新逻辑。
遮挡/NLOS 降级状态机 视觉丢失目标时切UWB、UWB多径异常时用视觉修正——这个状态判断和切换逻辑没有现成模块，需要自己写一个监控节点。
Web Dashboard 前端页面 rosbridge解决了"数据怎么传到浏览器"，但页面本身（实时坐标、误差曲线、热力图的UI设计）要自己用HTML/JS或React写。
精度评估与统计脚本 RMSE、CEP50/95、误差热力图这些针对你们测试点位设计的评估代码，需要自己写数据后处理脚本（可以参考 ros2-ekf-localization 里的评估思路）。
全系统集成 launch 文件 把以上所有模块（驱动、检测、融合、可视化）串成一套能一键启动的 ROS2 launch 文件和参数配置，这是把"缝合"落到工程上的最后一步，必须自己做。
