# 参考特征至目标米制状态的在线链路

本记录对应D02/D03/D04、F03/F05和H01的新增实现。它补上参考图像素轨迹到map米制状态的多帧分支；已知几何PnP的在线关键点生产、多Tag目标基准、融合与展示仍是独立待补项。

## 输入和目标坐标定义

`superpoint_motion_node`的`target_tracks`每个轨迹新增：

- `reference_id`：参考像素坐标及描述子的SHA256，标识固定参考中的特征编号；参考变更会重置米制窗口。
- `anchor_feature_id`、`anchor_reference_px`：用于定义目标输出坐标的一个固定参考特征及其实际参考图像位置。
- `motion_model`：`static`或`constant_velocity`。未指定时默认后者，不自动将未知目标视为静止。
- `feature_observations`：经过双向匹配和局部几何内点验证的`feature_id/pixel_px/reference_pixel_px`列表。身份有歧义、当前未观测或watchdog失效时不提供新的对应。

参考注册请求可以附加`motion_model`与`anchor_reference_px`。指定像素选择ROI中最近的真实SuperPoint特征，输出会报告实际选中像素；省略时选择最靠近参考ROI中心的特征。

该分支报告的是**目标表面固定参考特征点的位置**，不是自动推断物体几何中心。始终使用同一特征ID，不以每帧框中心或不同可见特征的平均值替换。当该点不可见时报告`target_reference_anchor_not_visible`；不能通过换点掩盖丢失。需要特定几何原点/完整姿态的目标仍需已知几何PnP等分支。

误差评估必须使用同一参考点的真值，或使用经过标定的参考点到目标原点变换；不能把此输出直接与物体中心真值比较后宣称定位误差。

## 平台位姿与采样时刻

`target_metric_node`订阅`/nexus/platform/odom`，只接受`map → base_link`、原采样时间、有效单位四元数及半正定6×6协方差。不得把UWB机载标签位置直接作为外部目标位置。

`PoseTimeline`按原图像采样时间查询：有精确时刻则直接使用，否则需要前后平台位姿包围该时刻，在有限间隔内插值平移与SO(3)旋转。没有后续位姿时在有界队列等待；不使用最新收到的位姿替换，也不无约束外推。最大间隔默认0.25秒，缓存默认5秒/256条，均为可配置算法边界。

插值协方差包含端点位姿Jacobian与运动插值噪声。端点相关性未知时使用`2(Pa+Pb)`的保守界；插值模型采用配置中的线/角加速度sigma估算误差。跨越接近180度旋转分支、无包围位姿或时间间隔过大时不能生成有效平台观测。等待原因通过`target_geometry_status`发布，且不每个定时器周期重复相同原因。

## 多帧目标求解

`solve_multiview`使用相机内参/畸变、`T_body_camera`与图像时刻平台位姿构建同一目标参考点的多条视线。

| 模型 | 状态 | 可观测性要求 |
|---|---|---|
| static | 当前map位置3维 | 目标静止假设、足够观测帧及有效视差 |
| constant_velocity | 当前map位置+速度6维 | 窗内匀速假设，联合位置/速度设计矩阵满秩；仅相机与目标均匀直线运动不能据此恢复唯一深度 |

线性多视线初始化 → 有界RANSAC候选 → 正深度/重投影共识 → 协方差加权Huber优化 → 当前帧内点检查 → 视差/条件数/速度检查。时间尺度在求解内归一化，输出速度及协方差转换回m/s。无视差、深度/速度不合理或当前帧为粗差时不输出伪造的新位置。

节点默认保留12帧、3秒窗口。启动时允许积累不足的视差/观测；粗差失败不替换已接受的窗口，处理超时不提交新窗口。身份歧义清除相应几何历史；参考或运动模型变化也重建窗口。该分支每次只使用保留的观测重新求解，不把上次结果当新的独立测量加入同一个窗口。

协方差包含像素测量噪声、平台位姿和外参。不同平台位姿可能共享估计历史，未知跨帧相关性使用`N × sum(P_i)`的保守界；外参作为跨帧共享变量传播一次，不随帧数错误地平均掉。线性化、所选运动模型及标定正确性仍是前提；此估计不是实机误差保证。

## ROS输出与兼容性

新增`nexus_msgs/TargetKinematicState`，在`/nexus/vision/target_kinematics`输出。保留原`TargetObservation`接口，未用默认单位四元数伪装未知姿态。

- Header是实际图像采样时间与map frame，另有接收时间、target_id、valid、state、reason和来源。
- `position_reference=reference_feature:<reference_id>:<anchor_feature_id>`明确位置定义。
- `position_observed/velocity_observed/orientation_observed`分别声明可观测分量。static分支的零速度属于假设，不作为实测速度输出；constant_velocity满秩时输出估计速度。当前多帧点分支不估计物体姿态。
- pose的位置单位m，velocity单位m/s，9×9协方差顺序为`[map位置, map速度, map固定轴旋转]`，对应单位m、m/s、rad。未知分量及其协方差条目填NaN，姿态未知时四元数也为NaN，消费者必须检查标志。
- 无效输出保留最后有效采样时间，不把旧坐标冒充新观测；过时失败不得覆盖更新的有效结果。
- `/nexus/vision/target_geometry_status`提供失败原因、内点时间、视差、条件数、耗时和是否使用平台插值；质量topic按既有20项特征契约发送重投影、内点率、延迟和可观测速度。

`static_visual.launch.py`默认启动目标身份与米制分支；需要本机已有平台odom生产者，以及实际模型和相机/外参标定。纯像素检查可设置`enable_target_geometry:=false`。配置模板`config/target_geometry_template.yaml`明确为unmeasured，不能直接运行冒充实测标定。

## 当前证据与剩余工作

- 数值测试验证静态点粗差拒绝、当前帧异常不刷新、匀速状态/退化、无基线拒绝、共有外参误差不被平均、非零安装杆臂/相机旋转、平台原时刻插值。
- DDS测试从参考图注册，经SuperPoint像素身份与特征对应，到平台位姿配对及静态/匀速米制输出；覆盖延迟平台输入、插值、超时回滚、恢复、未来时间拒绝及质量契约。
- 网络边界使用明确的合成特征。平台odom是合成数值输入，不能称为真实YOLO/SuperPoint运行或实机定位结果。
- 新米制状态尚未接入旧目标融合/可视化；联合相关性处理、真实边缘化、动态姿态、已知模型自动关键点与多Tag目标入口继续保留在逐项清单中。
