# ADR-005：冻结硬件到货前接口与坐标契约 V1

- 日期：2026-08-20
- 状态：accepted
- 负责人：项目组
- 关联任务/运行：步骤 02、03、05、06；硬件字段签核待执行

## 背景

硬件尚未到货，无法确认 FanciSwarm 实际 UWB 输出对象、轴向、单位、时间来源、相机 frame 或沙盘物理原点。但这些未知事实不应阻碍项目先冻结 ROS2 内部语义和拒绝规则；也不能用虚构的外参或硬件坐标填补空白。

## 决定

1. `base_link` 永远表示无人机飞行平台；`target_link` 永远表示外部目标。平台消息不得改名、复制或推断为目标观测。
2. ROS2 目标世界输出固定为 `/nexus/target/pose`，`frame_id=map`，长度单位为 m。`map` 采用右手系：`+z` 垂直沙盘台面向上，`+x/+y` 在台面内；物理原点和两个轴向基准点由标定运行填写，未填写前不发布真实世界坐标。
3. `camera_i` 使用相机驱动/`CameraInfo` 所声明的光学 frame；其轴向不得凭名称假定。`uwb_anchor_i` 表示第 i 个基站的天线参考点，坐标必须来自实测或经验证的 UWB→map 变换。
4. 厂商 UWB 原始坐标在语义确认前只能记为 `uwb_raw`。ROS1 适配层是唯一允许进行厘米→米或 NED↔ENU/`map` 转换的位置；转换必须有确认的输入轴向、单位和版本，未知时拒绝目标观测。
5. 每条目标观测必须有 `target_id`、`source_mode`、`frame_id`、米制单位、`sample_timestamp_ns`、`receive_timestamp_ns`、协方差、置信度和有效性。采样时间不能由接收时间替代。
6. `invalid_frame`、`invalid_unit`、`missing_target`、`stale`、`transport_error` 与无同步配对都是不可融合状态；不以零值、上一帧或其他来源补写。固定协方差融合只接受同一目标、同一 `map` frame、未过期且时间差在冻结阈值内的观测。

## 验证计划与结果

到货前：`nexus_channel_contract`、坐标变换、回放样例和融合测试必须验证上述语义。到货后：按首日验收清单把实际 topic、UWB 标签对象、单位、轴向、时间和相机 frame 填入记录；任一与本契约冲突的字段均需新增 ADR 和适配测试。

## 影响、回滚和后续动作

本 ADR 冻结内部表达而非物理外参；无法确认硬件输入时系统宁可输出无有效定位。硬件到货后只补事实字段和外参版本，不得改变平台/目标语义或静默改变单位。
