# 步骤 01：明确定位对象与验收边界

- 日期：2026-08-20
- 类型：执行指导
- 状态：draft
- 对应总计划：步骤 1
- 关联决定：`docs/decisions/2026-08-18_ADR-002_target-localization-scope.md`
- 本文范围：定义对象、测量模型、场景和验收证据；不讨论具体代码实现。

## 先给结论

第一步不是选算法，而是回答四个问题：定位谁、输出哪个物理点、用哪条观测链、用什么独立真值判断。无人机是传感器、通信和计算平台，最终输出必须是无人机之外目标在 `map` 中的位置。`base_link`、飞控 odometry 和 `target_link` 从第一份记录开始分开。

## 一、确定目标对象

“目标”必须对应一个实际可以拍照、测量、安装标签和重复放置的实体，不能只写“无人机目标”。记录目标形状、尺寸、材质、运动方式和可见表面。为目标分配唯一 `target_id`，并为目标指定固定物理参考点：几何中心、底部中心、标签安装板中心或任务规定点。

目标照片应标出 `target_link`，并记录它与视觉标签中心、UWB 天线中心之间的三维偏移。最终报告的位置表示这个参考点，不是任意角点或传感器天线点。

## 二、选择测量模型

### 模型 A：目标直接测量

目标携带 UWB 标签和视觉标记：

```text
UWB/tag_target ─┐
                ├─→ target_link → map
camera_i/tag ───┘
```

优点是两个来源都直接观测目标；代价是必须确认官方消息对应目标标签，并测量两个标签到 `target_link` 的偏移。

### 模型 B：平台间接测量

UWB 测无人机，视觉测目标相对无人机位置：

```text
UWB → base_link → camera_i → tag_target → target_link → map
```

优点是目标可较轻；代价是必须获得平台姿态、相机外参、目标标签外参和时间同步。平台位置不能直接写成目标位置。

### 模型选择记录

```text
measurement_model: direct_target / platform_relative
uwb_tag_object:
vision_tag_object:
target_link_definition:
platform_pose_required: yes / no
truth_method:
decision_owner:
decision_date:
```

两种模型不能混在同一次实验中；未选模型只能列为后续扩展。

## 三、定义验收场景

### 静态场景

目标固定在已知点，验证坐标和测量的基本准确性，对应 E001。需要规定点位、停留时间、重复轮次和真值复核。

### 动态场景

目标沿可重复轨迹移动，验证更新频率、延迟、轨迹误差和丢帧，对应 E002。动态数据不能回填 E001。

### 异常场景

遮挡视觉、改变 UWB 视线或断开一条链路，验证降级、恢复和报警，对应 E003。必须保留失败片段。

## 四、定义区域和指标

根据实体沙盘实际视场划分核心视觉区、过渡区和 UWB 兜底区。每个区域登记边界、目标高度、预期可用传感器和指标。5 cm、30 cm 等数字属于规划目标；只有正式实验达到预设条件后才能写成结果。

至少使用 RMSE、P50/P95、最大误差、可用率、更新频率、延迟和异常数。区域指标不能只报告一个全场平均值。

## 五、团队推进顺序

1. 目标负责人提出候选目标；
2. 硬件负责人确认标签、供电和安装；
3. 视觉负责人确认目标可检测性；
4. 测试负责人确认真值和重复放置方法；
5. 组长冻结首版模型、场景和指标；
6. 将未选方案记录为后续工作。

## 六、可直接借用的方案

- ADR-002 的外部目标边界和两种测量模型；
- 模块图中 `/nexus/target/pose` 作为 ROS2 主输出；
- `base_link`、`target_link`、`tag_target` 的命名；
- E001 的静态研究问题。

## 七、必须自行确定的内容

- 目标实体和物理参考点；
- 标签安装对象和位置；
- 沙盘区域边界；
- 真值测量工具和不确定度；
- 动态轨迹、异常方式和演示路线；
- 首版排除的扩展功能。

## 八、产出物

- 《目标与验收边界说明》；
- 测量模型决策记录；
- 目标照片和 `target_link` 标注图；
- 场景与区域定义表；
- 初版验收指标表；
- 未决问题清单。

## 九、通过与停止条件

### 通过条件

- 团队能说清定位对象和目标参考点；
- `base_link` 与 `target_link` 已分开；
- 首版测量模型已冻结；
- 每类场景有真值和验收问题；
- 规划目标没有被写成实测结果。

### 必须停止

- 不清楚 UWB 消息代表哪个标签；
- 目标无法重复放置或没有物理参考点；
- 真值不确定度大于目标指标；
- 团队仍混用平台和目标位置。

## 十、禁止越界

- 不得因为有官方 UWB 就声称获得目标位置；
- 不得因为能检测标签就声称完成世界坐标定位；
- 不得在没有真值时写“厘米级”；
- 不得把未验证的回传控制和动态飞行写成首版验收条件。
