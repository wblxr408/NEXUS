# 步骤 05：打通 UWB、视觉和 ROS1/ROS2 通道

- 日期：2026-08-20
- 类型：执行指导
- 状态：draft
- 对应总计划：步骤 5
- 关联资料：`docs/module-map (1).html`、`docs/architecture/hardware-integration.md`
- 本文范围：单传感器和跨 ROS 链路验收；不进行融合调参和精度结论。

## 先给结论

一次只接通一条链路：先证明官方 UWB 能稳定输出，再证明视觉能稳定检测，再证明 ROS1→ROS2 能不改变语义，最后才合并。出现误差时，必须能判断它来自传感器、通信、时间还是坐标，而不是所有模块同时开启后凭感觉猜。

## 一、开始前的准入条件

- 步骤 04 的硬件验收已通过；
- 标签安装对象已写入记录；
- 步骤 02 的字段和时间契约已冻结；
- 已准备 ROS1 原始记录和 ROS2 转换记录的位置；
- 已准备可重复的静态目标或平台状态场景。

缺少任一项时，只做桌面通信检查，不进入定位结果比较。

## 二、UWB/飞控链路

### 1. 基站与配置登记

记录四个基站的物理位置、高度、安装方向、通道、配置版本和环境。基站一旦用于正式数据，位置不得随意移动；移动后要回到步骤 06 重新标定。

### 2. 输出对象核对

通过 App、官方资料、日志字段或厂商确认，判断输出对应无人机标签、目标标签还是其他状态。若只确认是平台位置，必须标记为平台状态，不得命名为“目标 UWB”。

### 3. 静态稳定性检查

让被测对象停在一个可复测位置，记录一段连续数据，观察：

- 输出是否持续；
- 更新频率；
- 位置波动；
- 丢包和跳变；
- 飞控时间与 ROS 接收时间；
- 设备重启后的恢复情况。

此阶段只报告观测稳定性，不报告相对真值的精度，除非坐标和真值已经通过步骤 06 固化。

### 4. 原始测距边界

只有当厂商真正开放四基站原始测距，并且字段含义、时间和单位清楚时，才考虑模块图中 LS/鲁棒 LS 等离线参考。没有原始测距时，不做 Chan/Taylor/TDOA 或 Nooploop 的伪比较。

## 三、视觉链路

### 1. 输入确认

确认相机是否能提供原始帧、分辨率、帧率、快门类型、相机内参、图像时间戳和传输方式。不能假定 800 万像素机载相机一定能被 ROS 直接读取。

### 2. 单相机先行

先判断一台相机能否覆盖核心区，再使用 AprilTag 或 OpenCV ArUco 验证：

- 目标能否被检测；
- 标签尺寸和字典是否正确；
- 目标朝向变化是否影响检测；
- 遮挡和光照条件下的成功率；
- 重投影误差和图像延迟。

### 3. 多相机条件

只有在多路原始图像、同步时间戳、内参和固定外参都可用时，才进入 `caliscope` 或多相机三角测量路线。多相机数量本身不是精度保证，必须通过步骤 06 标定和步骤 07 实验验证。

### 4. 无观测行为

视觉不能检测到目标时，应输出明确的无观测状态、原因和最后有效时间。不能以上一帧坐标伪造当前有效数据。

## 四、ROS1→ROS2 通道

### 推荐顺序

1. 先传平台状态；
2. 再传未经融合的目标观测；
3. 再传坐标转换后的目标世界坐标；
4. 最后才考虑 ROS2→ROS1 回传。

### 逐项核对

- 消息类型和 schema 版本；
- 序号连续性；
- 采样时间是否保留；
- 接收时间是否另列；
- frame 是否原样或按约定转换；
- 单位是否为米；
- target ID 和 source mode 是否一致；
- 断桥、重连、乱序和重复消息如何处理。

### 记录两端数据

ROS1 原始记录用于证明硬件实际输出，ROS2 记录用于证明适配后的语义。两端都要保留，不要只保存最终展示数据。

## 五、可直接借用的方案

- 官方 FanciSwarm、Mcontroller V7 和 `fcu_core`；
- AprilTag、OpenCV ArUco；
- `caliscope` 多相机条件性参考；
- rosbridge/ros2 bag 作为数据出口；
- 模块图中的“官方层 → ROS2 算法层”分层。

## 六、必须自行确定的内容

- UWB 输出的标签对象；
- 相机输入接口和主相机；
- 单相机/多相机的启用条件；
- 通道实际部署位置、频率和重连规则；
- 无观测、过期、丢包和错误状态；
- 何时允许把一条链路纳入正式实验。

## 七、建议记录模板

```text
run_id:
uwb_anchor_config:
uwb_tag_object:
uwb_message_semantics:
vision_camera_id:
image_source:
image_rate:
image_timestamp_source:
bridge_method:
sample_to_receive_delay:
packet_loss:
reorder_count:
reconnect_count:
invalid_observation_policy:
operator:
```

## 八、产出物

- UWB 单独记录和稳定性说明；
- 视觉输入确认表和检测记录；
- ROS1→ROS2 映射表；
- 时间延迟、丢包和重连报告；
- 平台状态/目标观测语义核对表；
- 未确认接口清单。

## 九、通过与停止条件

### 通过条件

- 每个传感器可独立记录和回放；
- UWB 标签对象已确认；
- 视觉输入、时间戳和内参状态明确；
- 通道不改变单位、frame、时间和对象语义；
- 无效数据不会静默补写。

### 停止条件

- 只看到一个 XYZ 数值但不知道对象；
- 图像没有可靠时间戳；
- bridge 只能靠接收时间配对；
- ROS1 和 ROS2 的轴向或单位未核对；
- 多相机输入无法保证同步。

## 十、禁止越界

- 不把厂商标称精度当作本项目实测；
- 不在原始测距未开放时实现伪算法比较；
- 不把平台 odometry 直接转换成目标位置；
- 不在单传感器链路未稳定时启动融合和飞控回传。
