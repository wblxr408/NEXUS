# 步骤 03：硬件到货前完成最小软件骨架

- 日期：2026-08-20
- 类型：执行指导
- 状态：draft
- 对应总计划：步骤 3
- 关联计划：`docs/2026-08-18_plan_pre_hardware_work.md`
- 本文范围：规划模块边界、离线验证和模拟数据；不把测试样例写成真实结果。

## 先给结论

硬件到货前最值得做的是准备消息语义、坐标链、评估口径和启动结构。骨架应足够小，能在固定样例上验证主链路；真实硬件、真实外参和精度结论留到后续步骤。

## 一、确定软件边界

| 模块 | 负责什么 | 不负责什么 |
|---|---|---|
| `nexus_msgs` | 消息语义 | 厂商协议解析 |
| 视觉适配 | 图像、标记和视觉观测接口 | 世界坐标真值 |
| 坐标转换 | frame、刚体变换和单位核对 | 自动猜外参 |
| 融合 | 合法观测组合和来源状态 | 飞控安全闭环 |
| 评估 | 误差、可用率和延迟 | 重新拟合真值 |
| bringup | 参数、启动和录包入口 | 临时调参掩盖失败 |
| Dashboard | 状态和结果展示 | 定位、融合和指标计算 |

每个模块都要写输入、输出、依赖、无效行为和验证方式。模块之间传递语义化消息，不直接共享未登记的本地文件或硬编码路径。

## 二、设计模拟数据

模拟数据必须标注 `data_type=test_sample`，至少覆盖：

- 目标静止；
- 两个来源带不同协方差；
- 观测过期；
- frame 不一致；
- 单位错误；
- 视觉暂时丢失；
- UWB 与视觉不同步；
- 两个来源同时无效。

每个样例记录构造目的、输入假设、预期输出和不能代表的真实结论。

## 三、建立离线回放闭环

```text
模拟观测
  ↓ 字段/时间/frame 校验
坐标变换
  ↓
单源目标输出
  ↓
固定规则融合
  ↓
与模拟真值配对
  ↓
指标和状态报告
```

先离线后实时，可以在没有硬件时发现坐标、字段和统计问题。回放输出应能显示来源模式、有效性和输入组合，而不只显示一个最终坐标。

## 四、视觉模块的准备边界

模块图建议使用 AprilTag 或 OpenCV ArUco 作为候选，但不能写死相机型号、分辨率、帧率、标签字典、标签尺寸或相机数量。骨架只需规定图像、相机参数、检测结果、观测时间和无目标状态。`caliscope` 只是多相机条件性参考。

## 五、坐标转换模块的准备边界

前置阶段验证：单位转换、轴向变换、刚体变换组合、变换方向检查和缺少外参时拒绝输出。不得填真实沙盘坐标、基站位置或假设相机外参。真实参数必须由标定运行提供。

## 六、融合模块的准备边界

前置阶段验证：单源直通、固定协方差组合、过期拒绝、frame 不一致拒绝、无观测无效输出和来源模式保留。没有 E001 数据时不要调 EKF/UKF、动态权重或图优化。

## 七、评估工具的准备边界

输入至少包含：

```text
timestamp_ns,receive_timestamp_ns,
target_id,frame,x_m,y_m,z_m,
source_mode,validity,truth_id,data_type
```

报告必须说明坐标系、单位、真值来源、有效样本、缺失样本、异常规则和 `test_sample/measured` 标记。

## 八、可直接借用的方案

- ROS2 `tf2` 的坐标树组织；
- AprilTag、OpenCV ArUco；
- `caliscope` 多相机参考；
- 官方 `fcu_core`、FanciSwarm、rosbridge 的依赖边界；
- E001 的指标和运行目录规则。

## 九、必须自行确定的内容

- 包之间的输入输出责任；
- 两种测量模型的独立入口；
- 模拟样例覆盖范围；
- 评估字段和统计口径；
- 首版不做的复杂功能。

## 十二、通过与停止条件

### 通过条件

- 模拟消息能沿主链路流动；
- 单位、frame、时间错误能被发现；
- 单源和固定规则融合可解释；
- 所有样例标为测试数据；
- 没有真实外参和精度数字硬编码。

### 停止条件

- 模拟数据使用未经确认的硬件语义；
- 输出无法区分测试样例和实测；
- 缺少外参时仍自动生成坐标；
- 为了完整性加入没有验证依据的复杂算法。

## 十三、禁止越界

- 不把模拟样例放进正式实验目录；
- 不把代码已写表述成精度已达标；
- 不提前假设多相机、D435、原始 UWB 测距一定可用；
- 不在前置阶段替换飞控内置 EKF 或控制闭环。
